# 涌线 -- crowd line

**涌现式地铁调度沙盒**。以真实城市线网为舞台，玩家只调规则（限流、车辆段编组、封站、跳站、广播……），乘客自己涌、自己堵、自己疏解，最终以积分评价经营水平。

> 基于《涌线--crowd line》游戏策划案 v0.2 实现的 Godot 4.7.2 可玩 Demo。

---

## 快速开始

1. 用 **Godot 4.7.2** 打开本项目（`project.godot`）。
2. 直接运行主场景 `res://scenes/main.tscn`（F5）。
3. 主菜单选择线网与难度池，点击「开始运营」。

> 引擎定位：`F:\Godot_project\涌线--crowd-line\`。渲染方式为 Mobile（兼容移动端），Windows 驱动 d3d12。

## 已实现功能（对照策划案 v0.2）

### 核心循环与涌现
- 乘客 Agent：最短路径寻路（BFS）、耐心衰减、从众性、恐慌传播。
- 列车：沿线运行、全程班次门控（同站同方向自动拉开、不扎堆）、容量与编组、登降、**延误传播**（晚点列车在换乘站波及其他线路）。
- 站点：容量上限、密度阈值、换乘。
- 涌现：限流→需求转移、车辆段编组→运力变化、封站→人流改道、恐慌→踩踏风险。

### 时间变化系统（v0.2 新增）
- 昼夜循环：清晨 / 早高峰 / 平峰 / 午间 / 午后 / 晚高峰 / 夜间 / 深夜。
- 时间驱动参数：需求曲线、耐心衰减速率、从众性、背景色平滑过渡。
- 天气系统：晴 / 阴 / 小雨 / 暴雨 / 雪 / 雾，叠加需求与速度倍率，GPU 粒子（雨 / 雪）。

### 三段式视野与成分云
- 远景：乘客合并为半透明「成分云」，颜色表示状态构成，密度表示压力。
- 中景：乘客为小圆点，线路与站点清晰（Mini Metro 风格）。
- 近景：放大可见站点环、恐慌高亮、列车满载指示。
- 缩放过渡：云 ↔ 圆点交叉淡入淡出。

### 玩家操作
限流（降低进站速率）、**升级车辆**（先建车辆段，再下达加挂指令）、封站（强制改道）、跳站（列车不停靠）、广播（平息恐慌 / 引导改道，长冷却）。

四个非车辆段操作都要花资源：限流 15 / 封站 12 / 跳站 12 / 广播 20。资源有多个出口，才有取舍。

### 列车
车身是**镂空胶囊体**，镂空部分的填充量就是载客率；出站加速、进站减速（`Config.train_speed_factor()`），
车头灯在低速进站时更亮、刹车时尾端泛红；靠站剩余时间是一圈逐渐"排空"的圆环。
全貌段（远景）车身会自动拉长加粗，免得一整张图上认不出来。

### 天气与事件（现实依据集中在 `resources/real_world.json`）
天气按**气候带**取用并按权重**每 70~150 秒自然轮替**：晴 / 阴 / 小雨 / 暴雨 / 雷暴 / 台风 / 酷热 / 大雾 / 雪。
每张图声明自己的气候带与**禁用天气**，所以**南方线网永远不会下雪**。
事件分两类：**场馆类**（只在真实场馆所在的站发生，例如温州演唱会只在奥体中心）与**设施/天气类**（哪站都可能）。
**开局只从"晴/阴"这类温和天气里抽**，免得特殊天气撞上开局早高峰。

### 运营日志与视野滑钮（右侧）
- **日志按钮**：展开列出本局全部**特殊事件 / 特殊天气 / 玩家操作**，每条带**开始 → 结束**时间
  （天气这类有持续时段，事件与操作是瞬时点）。
- **视野滑钮**：一段竖直轨道，上面 **3 个站点就是三段视野锚点**，站点上下各多出一小截轨道表示
  "还能再放大/缩小一点"，轨道上的**列车表示当前视野**；平时半透明，悬浮或拖动时不透明。

### 时间控制与暂停
时间面板只有两个键：**暂停**（弹出运营概览：评级 / 总分 / 运营时长 / 五项指标 / 继续 / 退出到主菜单）
与**加速 2×**（再按一次回原速）。

### 车辆段与编组延长（核心运力机制）
- 每线一个车辆段，**优先取线网 JSON 的 `depot_station`，没声明就自动选离线路中点最近的非换乘站**。
- 首次使用「升级车辆」先建段；之后每次点，是**下达一张加挂指令**（段站出现黄色脉冲环）。
- **兑现是就地发生的**：线路上下一列停靠段站的列车在该站多停几秒（平峰 5s / 高峰 12s）挂上一节，
  期间照常开门上下客——**该车不离开线路，车队规模不变**（不再是原来"抽走一列车 24 秒"）。
- 编组 +1 节，定员 = 节数 × 40（初始 2 节 = 80 人，上限 6 节 = 240 人）。
- 同一条线每加挂一次费用递增，且**同时只能有一张未兑现的指令**。
- 设计意图：**平峰下手，高峰收获**。加挂的价格与占站台时长都随客流负荷浮动（平峰 ×0.75 价 / 5s，高峰 ×1.35 价 / 12s），而它买来的运力恰恰要到高峰才用得上。这取代了原「加车」（凭空生成新车、收益即时且可无限叠加、决策退化为点按钮）。

### 积分评价
准点率（25%）、满意度（25%）、吞吐量（20%）、安全分（20%）、效率分（10%），评级 D/C/B/A/S。

### 肉鸽机制（只改参数）
- 随机事件：演唱会散场、暴雨、信号故障、出口关闭、票价优惠、设备检修。
- 每 2 分钟三选一升级：快速闸机、智能广播、检修车间（加挂费用 -30% / 占站台时长 -20%）、宽敞站台、应急通道。

### 失败条件
踩踏风险、全网瘫痪、满意度归零。

### 线网与线路池
共 7 张线网、5 个池。主菜单先选「线路池」，再从中**随机抽一张图**（`scripts/autoload/network_pool.gd`）：

| 池 | 标识 | 内容 |
| --- | --- | --- |
| 教程池 | `tutorial` | `tutorial_basics`（8 站 2 线；开局资源 150、客流 ×0.7、不触发随机事件，配 6 步操作引导） |
| 基础池 ★ | `entry` | 温州 S1、里斯本蓝线 |
| 进阶池 ★★ | `advance` | 香港荃湾+观塘、台北十字线 |
| 硬核池 ★★★ | `hardcore` | 重庆、成都 |
| 无限模式 ∞ | `infinite` | **已实现**：不限时，每 75 秒加 1 站 + 1 线（上限 12 线），客流 ×1.09/波、事件越来越密、吞吐目标 +260/波 |

## 已知简化

- **美术**：场景已接入 `assets/icons/` 的 22 个图标（操作栏、时间控制、评级徽章、列车/乘客/站点、天气粒子），其余仍为程序化绘制（`_draw`）；策划案里的地标剪影、音频基调未实现。
- **无限模式**：已实现（`InfiniteDirector` 每波加站加线；`_check_failure` 里 `not infinite_mode` 直接绕开"时间到"）。
  `NetworkPool` 的 `infinite` 池 `members` **故意留空**——抽图时走 `all_network_ids()` 从全部真实线网里选。
- **移动端缩放 UI**：目前仅实现滚轮缩放，右侧拖动缩放待补。
- **着色器**：有 3 个 `.gdshader`——`bg_paper`（亮色纸面：渐变 + 极淡点阵 + 缓慢漂移 + 暗角）、
  `passenger_dot`（乘客点：软芯呼吸 + 向外扩散的涟漪）、`train_body`（列车：灯带随车速滚动、车头灯、刹车灯）。
  昼夜色温仍用代码 `lerp` 调色；后处理（Bloom / 色差 / 暗角）未做。
- **主菜单与结算已统一成亮色主题**（共享资源 `resources/theme_light.tres`），下拉箭头是本地生成的
  `assets/icons/icon_chevron_down.png`（零授权问题，可随时改色重生成）。

## 引擎与测试

- 引擎：Godot 4.7.2 stable。
- 模拟逻辑已通过 headless 自测（温州吞吐 432、香港换乘吞吐 1358，双线换乘正常）。
- 六个 headless 验收工具（`tests/`）：
  - `depot_bench.tscn` —— 车辆段手感基准。策略 `none` / `build` / `greedy` / `offpeak` / `late`，
    输出总分、服务人数、满意度、峰值密度、指令时段分布。`none` 策略必须与改造前**逐位相同**，用来守住"改造无副作用"。
  - `op_price_test.tscn` —— 定点断言（操作扣费、车辆段选址、分时定价、就地加挂），25 项、失败退出码 1。
  - `ui_smoke_test.tscn` —— HUD / GameView 运行时冒烟 32 项。删掉模拟层函数后 UI 里的残留调用**编译期查不出**
    （GDScript 动态调用），只有真跑 `HUD._process()` 才会炸；它会遍历选择态与车辆段四态、核对按钮价格与置灰。
  - `infinite_test.tscn` —— 无限模式验收 24 项（新站不越界、扩张后仍全站可达、顶满线路上限、不看钟、普通模式不被带坏）。
  - `wiring_probe.tscn` —— 运行时接线自检。专抓**静默失败**：`theme` 误挂在 `CanvasLayer` 上（UI 全体回落 Godot
    默认深色主题、不报任何错）、渲染层 `sim` 没接、材质没挂上（→ 着色器变成死代码）。
  - `real_world_test.tscn` —— 现实依据表验收。核心断言是**表里写的场馆站名必须真的存在于对应地图**
    （写错不会报错、只会静默失效），以及"南方线网不会下雪""温州演唱会只落在奥体中心"。
- 可视化核对工具 `shot.tscn`（**必须开真窗口**：`--headless` 是空渲染器，视口纹理里什么都没有）：

  ```powershell
  $godot = "D:\下载\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64_console.exe"
  $root  = "F:\Godot_project\涌线--crowd-line"
  # 局内指定缩放：<线网> <难度> <缩放> <先跑多少游戏秒> <输出> [取景站号]
  & $godot --path $root res://tests/shot.tscn -- hongkong_tw_kt advance 2.6 45 res://tests/ref.png
  # 只渲染某个界面场景（主菜单 / 结算）
  & $godot --path $root res://tests/shot.tscn -- scene res://scenes/main.tscn res://tests/_menu.png
  ```

  它会在 0.8 秒后再抓一帧并打印**像素差**（模拟已冻住，差异只可能来自着色器/自绘动画），
  这是"动效到底有没有在动"的客观判据。注意必须多档灵敏度：背景点阵漂移很慢，单帧只差 1~2/255，
  用单一阈值（如 >8）会得出"没有动效"的错误结论。
- **踩过的坑（都会静默失败，务必记住）**：
  - `theme` 只能挂在 `Control` / `Window` 上。挂在 `CanvasLayer` 上**不会报错**，整棵 UI 静默回落默认主题。
  - GDScript 运行时错误会**中断 `_ready()` 的剩余部分**，连末尾的 `get_tree().quit()` 一起跳过 →
    headless 进程永久挂死且零输出。**判据：无输出又不退出 = 有错误，不是"跑得慢"。**
  - PS 5.1 的 `Get-Content` 默认按 GBK 解码，会把 UTF-8 中文源码的行数读少；要用
    `[System.IO.File]::ReadAllLines($f).Count`。
  - **新增 PNG/SVG 素材后要跑一次导入**，否则场景引用它会报 `No loader found for resource …`：
    `& $godot --headless --import --path $root`。
  - **`Train.from_idx` / `to_idx` 是本线 `station_ids` 的下标，不是站点 id**：画车必须
    `sim.stations[line.station_ids[idx]]`。漏掉这层间接寻址会把所有线的列车画到"全局第 N 号站"上，
    表现为「所有列车挤在一条线上」（已修，`wiring_probe` §4 有断言盯着）。
