# 《涌线--crowd line》游戏策划案 v0.1

**引擎：** Godot 4.7.2  
**平台：** 双端  
**开发周期：** 2 周  
**团队：** 3 人  
**美术定位：** 极简几何 + 手绘图标 + 统一霓虹色调  
**核心定位：** 涌现式地铁调度沙盒，真实线网为舞台，规则驱动涌现，玩家只调参数不直接控制乘客。  

## 1. 一句话概念

玩家从真实城市地铁线网中选择一张图，在限定时间内通过限流、加车、封站、广播等手段，让客流自己涌、自己堵、自己疏解，最终以积分评价经营水平。无限模式持续挑战递增难度。肉鸽机制只改参数，不改规则，涌现本质不变。

## 2. 核心体验

- **真实感**：线网来自真实城市，站点名称、换乘关系、线路走向有据可查。
- **涌现感**：乘客自己涌出来，拥堵自己形成，玩家只能改规则。
- **决策感**：限流还是加车？封站还是广播？每个选择都有代价。
- **评价感**：积分量化经营水平，可重复挑战、对比策略。
- **肉鸽感**：每局随机事件和升级，但核心涌现机制不变。

## 3. 核心循环

```
观察客流 → 识别压力点 → 做出调度决策 → 系统响应 → 产生新涌现 → 再观察
```

单局时长：5—12 分钟（无限模式除外）。  
失败条件：踩踏风险、全网瘫痪、满意度归零。  
成功条件：安全、准点、吞吐量达标，积分评级。

## 4. 游戏模式总览

| 模式     | 线网来源          | 时长    | 目标               | 难度 |
| -------- | ----------------- | ------- | ------------------ | ---- |
| 入门池   | 小型城市/单线     | 5 分钟  | 安全运营，积分达标 | ★    |
| 进阶池   | 中型城市/多线     | 8 分钟  | 高效运营，积分更高 | ★★   |
| 硬核池   | 大型城市/密集线网 | 12 分钟 | 极限运营，积分挑战 | ★★★  |
| 无限模式 | 随机生成/组合线网 | 无上限  | 存活尽可能久       | 递增 |

## 5. 难度池详细设计

### 5.1 入门池（★）

**线网特征：** 1—2 条线，5—8 个站，1 个换乘站。  
**真实来源示例：** 哥本哈根 M1/M2、里斯本蓝线、成都 1 号线早期段、杭州 1 号线早期段、曼谷 BTS 素坤逸线。  
**客流特征：** 单峰或双峰，节奏慢，异常少。  
**目标：** 积分 1000 通关，熟悉操作与涌现。  
**典型时长：** 5 分钟。

### 5.2 进阶池（★★）

**线网特征：** 3—5 条线，15—25 个站，3—5 个换乘站。  
**真实来源示例：** 新加坡 MRT 早期线网、香港荃湾线+观塘线+港岛线、台北淡水信义线+板南线、武汉 2+4 号线、成都 1/2/3 号线组合。  
**客流特征：** 明显早晚高峰，换乘压力大，偶发异常。  
**目标：** 8 分钟内准点率与满意度达标，积分 3000。  
**典型时长：** 8 分钟。

### 5.3 硬核池（★★★）

**线网特征：** 8 条线以上，50+ 站，10+ 换乘站，环线+放射线。  
**真实来源示例：** 北京、上海、东京、伦敦、巴黎、纽约、莫斯科地铁全网。  
**客流特征：** 潮汐流、级联延误、多线耦合、突发大客流。  
**目标：** 12 分钟内尽量不瘫痪，积分 6000。  
**典型时长：** 12 分钟。

### 5.4 无限模式

**线网来源：** 从真实线网随机抽取线路组合，或程序化生成。  
**规则：** 每 3 分钟新增 1 条线或 1 个换乘站，事件频率递增。  
**目标：** 存活尽可能久，积分累积。  
**结束条件：** 全网瘫痪或满意度归零。  
**特色：** 每局线网不同，肉鸽升级每局不同。

## 6. 积分评价体系

### 6.1 基础指标

| 指标   | 说明                   | 权重 |
| ------ | ---------------------- | ---- |
| 准点率 | 列车到达准点比例       | 25%  |
| 满意度 | 乘客平均耐心剩余       | 25%  |
| 吞吐量 | 总运送人数             | 20%  |
| 安全分 | 无踩踏、无恐慌事件     | 20%  |
| 效率分 | 平均等待时间、换乘时间 | 10%  |

### 6.2 积分公式（示例）

```
总分 = 准点率 × 1000 + 满意度 × 1000 + 吞吐量系数 × 800 + 安全分 × 800 + 效率分 × 400
```

### 6.3 评级

| 积分      | 评级 |
| --------- | ---- |
| < 1000    | D    |
| 1000—2999 | C    |
| 3000—4999 | B    |
| 5000—6999 | A    |
| ≥ 7000    | S    |

### 6.4 结算展示

- 积分明细
- 拥堵热力图回放
- 关键时刻标记（最大拥堵、最佳决策、失误点）
- 与历史最佳对比

## 7. 肉鸽机制（不偏离涌现本质）

### 7.1 原则

- 肉鸽只改变**规则和参数**，不直接改变客流结果。
- 玩家不能直接生成或删除乘客。
- 所有随机事件都通过反馈循环影响涌现。

### 7.2 每局随机

- **线网变体**：同一城市不同线路组合。
- **初始事件**：开局随机 1 个正面 + 1 个负面。
- **升级选择**：每 2 分钟三选一。
- **异常事件**：随机时间触发。

### 7.3 升级示例

| 升级     | 效果              | 代价          |
| -------- | ----------------- | ------------- |
| 快速闸机 | 进站速度 +20%     | 满意度 -5%    |
| 智能广播 | 乘客改道概率 +15% | 冷却 +30s     |
| 备用列车 | 加车成本 -30%     | 初始资源 -20% |
| 宽敞站台 | 站台容量 +25%     | 建设时间 +10s |
| 应急通道 | 封站副作用 -50%   | 限流效果 -10% |

### 7.4 随机事件示例

| 事件       | 效果                     |
| ---------- | ------------------------ |
| 演唱会散场 | 某站短时大客流           |
| 暴雨       | 整体需求 +20%，速度 -10% |
| 信号故障   | 某线延误传播             |
| 出口关闭   | 某站容量 -30%            |
| 票价优惠   | 需求 +15%，持续 1 分钟   |
| 设备检修   | 某站闸机 -50%            |

## 8. 游戏对象与玩家操作

### 乘客 Agent

每个乘客只有简单规则：去目的地、选最短路径、避开拥挤、跟人走、耐心有限、从众/恐慌。  
属性：起点、终点、耐心、速度、从众性、信息获取。

### 地铁列车

容量、班次、速度、延误传播。一条线晚点可能波及换乘站。

### 站点

闸机、站台、换乘通道、出入口。每个站点有容量上限和密度阈值。

### 玩家操作

| 操作   | 效果         | 成本       |
| ------ | ------------ | ---------- |
| 限流   | 降低进站速率 | 满意度下降 |
| 加车   | 提升运力     | 资源消耗   |
| 跳站   | 缓解某站压力 | 其他站积压 |
| 封站   | 强制改变人流 | 满意度大降 |
| 广播   | 引导路径选择 | 冷却长     |
| 调班次 | 长期影响需求 | 延迟生效   |

## 9. 涌现从哪来

- 乘客避拥挤 → 人流转向 → 新拥堵点。
- 列车延误 → 站台积压 → 换乘通道堵塞 → 级联失效。
- 从众/恐慌 → 局部密度突变 → 踩踏风险。
- 玩家限流 → 站外排队 → 需求转移 → 邻站爆满。

这些都不是脚本，是规则互动的结果。

## 10. 游戏场景样例阐释

### 场景 1：入门池——哥本哈根 M1/M2/温州S1S2

一条线，7 个站，无换乘。5 分钟，客流平稳。玩家操作限流、加车。目标积分 1000。教学重点：理解乘客自己涌、热力图、基本操作。画面：深蓝背景，青色线路，白色站点，绿色乘客点缓慢移动。

### 场景 2：进阶池——香港荃湾线 + 观塘线

两条线，18 个站，2 个换乘站（太子、旺角）。8 分钟，早晚高峰。随机暴雨或信号故障。玩家操作限流、加车、跳站、广播。目标积分 3000。教学重点：换乘压力、级联延误、广播引导。画面：品红与青色双线交织，换乘站白色圆环闪烁，热力图从绿变黄。

### 场景 3：硬核池——北京地铁全网

20+ 条线，400+ 站，50+ 换乘站。12 分钟，极端潮汐。事件：演唱会散场、暴雨、信号故障、出口关闭。玩家操作全部，多线协同。目标积分 6000，不瘫痪。教学重点：级联失效、多线耦合、资源分配。画面：密集霓虹线网，热力图频繁变红，Bloom 爆发，屏幕震动。

### 场景 4：无限模式——随机组合线网

从真实线网随机抽取 2 条线开始，每 3 分钟新增 1 条。无上限，事件频率递增。每 2 分钟随机 1 个事件。玩家操作全部，加肉鸽升级。目标存活尽可能久。教学重点：适应、取舍、长期规划。画面：线网逐渐扩展，颜色随机但统一霓虹风格，事件特效叠加。

### 场景 5：异常爆发——东京 Metro 新宿站

新宿站为核心，多条线交汇。3 分钟短局，突然大客流。事件：演唱会散场 + 暴雨。玩家操作限流、封站、广播、加车。目标避免踩踏，积分 2000。教学重点：应急决策、恐慌传播、从众行为。画面：红色热力图爆炸，Bloom 炸开，人群涌出，警报声。

## 11. 美术风格与着色器

### 定位

极简数据可视化 + 霓虹地铁图 + 手绘图标点缀。

### 统一规范

- **背景**：深灰/深蓝（#1a1a2e）
- **线路**：高饱和霓虹（青、品红、黄、绿）
- **乘客**：小圆点，颜色表示状态（绿=正常，黄=等待，红=拥堵，紫=恐慌）
- **站点**：白色圆环，大小表示容量
- **热力图**：绿→黄→红→白
- **UI**：半透明深色面板 + 霓虹描边
- **手绘素材**：仅用于图标、Logo、教程插图，风格统一为单色线稿 + 霓虹填充

### 着色器实现

- 密度场热力图
- 流线/方向场
- 实例化乘客
- Bloom、色差、径向模糊
- 历史帧反馈（拖尾、潮汐）

### 音效

- 人群声随密度升高
- 警报、广播、心跳
- 异常触发时音效突变

## 12. 技术架构

```
模拟层：乘客 Agent + 列车 + 站点 + 环境规则
   ↓
预测层（可选）：时间序列模型 → 预测未来客流
   ↓
反馈层：着色器可视化 + UI + 音效 + 事件系统
   ↓
玩家层：限流/加车/封站/广播/升级
   ↓
回到模拟层
```

## 13. 真实线网数据来源

| 来源           | 内容               | 格式        |
| -------------- | ------------------ | ----------- |
| OpenStreetMap  | 线路、站点坐标     | XML/GeoJSON |
| 各城市地铁官网 | 线路图、站点名     | 手动录入    |
| Wikipedia      | 线路历史、换乘关系 | 手动整理    |
| 开源数据集     | 客流 OD、时刻表    | CSV/JSON    |

**简化处理：** 不追求 1:1 还原，只保留线路拓扑、换乘关系、站点名称。客流用需求模型生成，不依赖真实客流数据。站点坐标可简化，保持相对位置即可。

## 14. 两周并行开发任务

### 第 1 周：核心系统

**成员 A：模拟系统**

- Godot 项目结构、主循环
- 乘客 Agent：生成、移动、路径、排队
- 需求生成：OD、泊松到达、时段曲线
- 站点与列车基础逻辑
- 真实线网导入工具（JSON → Godot Resource）
- 输出：可运行客流模拟

**成员 B：渲染与反馈**

- 着色器：热力图、流场、实例化乘客
- 站点、线路、列车程序化渲染
- 后处理：Bloom、色差、历史帧反馈
- 相机控制
- 输出：可视化模拟结果

**成员 C：游戏框架与 UI**

- 状态机：菜单、难度池、游戏、结算、无限模式
- 玩家操作：限流、加车、跳站、封站、广播
- 积分系统、评级
- 肉鸽升级界面、随机事件系统
- 输出：可操作游戏外壳

**第 1 周末联调：** 模拟 + 渲染 + UI 首次集成。

### 第 2 周：打磨与内容

**成员 A：模拟深化**

- 延误传播、级联失效
- 从众/恐慌
- 异常场景
- 真实线网数据整理
- 平衡调参

**成员 B：反馈强化**

- 爆发特效、音效
- 手绘图标、Logo、教程插图
- 视觉统一规范
- 性能优化

**成员 C：内容与集成**

- 难度池关卡设计
- 教程、引导
- 结算、积分展示
- 无限模式
- 存档、设置、打包

## 15. 接口约定

三人并行开发前，先约定以下接口：

- **模拟 → 渲染**：乘客位置、状态、密度场、流场
- **模拟 → UI**：站点密度、列车满载、准点率、满意度
- **UI → 模拟**：玩家操作指令、参数调整
- **事件系统**：异常触发、警报、音效事件
- **数据格式**：统一用 Godot Resource 或 Dictionary

## 16. 最小可行原型

先做一条线、3 个站、2 种乘客、3 个操作：

1. 乘客生成与移动
2. 热力图显示密度
3. 限流、加车、封站
4. 一个异常场景：演唱会散场
5. 一个失败条件：踩踏风险

跑通后再扩展多线、换乘、级联失效、更多事件。

## 18. 风险与对策

| 风险                 | 对策                                      |
| -------------------- | ----------------------------------------- |
| 真实线网数据整理耗时 | 先做 1—2 个城市，其余用程序化生成         |
| 模拟性能不足         | 低分辨率模拟，GPU 实例化，限制 Agent 数量 |
| 涌现不明显           | 调参：增强反馈循环，提高阈值敏感度        |
| 美术不统一           | 先定色板和线条规范，所有素材按规范        |
| 两周做不完           | 砍内容：先保证入门池可玩，再扩展          |
| 肉鸽偏离涌现         | 升级和事件只改参数，不改规则结构          |

## 19. 一句话总结

**真实线网为舞台，三种难度池 + 无限模式，限时经营 + 积分评价，肉鸽只改参数不改规则；乘客自己涌，玩家只调规则，着色器负责视觉爆发，三人两周并行开发，先跑通入门池再扩展。**
