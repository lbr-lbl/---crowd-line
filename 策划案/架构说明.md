# 架构说明

《涌线 -- crowd line》采用**三层解耦 + 事件总线**架构：模拟层独立演算涌现，渲染层与 UI 层只读模拟状态、通过信号通信。

---

## 1. 整体分层

```
┌─────────────────────────────────────────────┐
│  模拟层 simulation/                          │
│  Simulation（编排）                           │
│    ├ TimeSystem    昼夜循环、时段参数          │
│    ├ WeatherSystem 天气与参数倍率              │
│    ├ Station/Line/Train/Passenger 数据类      │
│    ├ ScoreSystem  积分五维                    │
│    ├ EventSystem  随机事件 + 肉鸽升级          │
│    └ InfiniteDirector 无限模式导演（每波加站加线）│
└──────────────────┬──────────────────────────┘
                   │ 只读查询 / 指令
┌──────────────────▼──────────────────────────┐
│  渲染层 rendering/（都是只读 sim 的 Node2D）    │
│  GameView         热力/线路/车辆段/站点/成分云  │
│  RouteGeometry    轨道几何（共端点线错开 + 站点胶囊）│
│  PassengerLayer   站台上的乘客点（挂点着色器）  │
│  TrainLayer       每线一个 LineTrainView 子节点 │
│  LineTrainView    车身（挂车着色器）+ 各种进度环│
│  BackgroundLayer  亮色纸面（挂 bg_paper 着色器）│
│  CameraController 三段式视野、点击选择          │
│  WeatherParticles 雨/雪粒子                    │
└──────────────────┬──────────────────────────┘
                   │ EventBus 信号
┌──────────────────▼──────────────────────────┐
│  UI 层 ui/（界面本体在 scenes/*.tscn）         │
│  HUD / MainMenu / Settlement / UpgradeUI / TutorialOverlay │
└─────────────────────────────────────────────┘
```

**场景化（重要约定）**：界面与单局编排**不再是"全在 `_ready()` 里 `new()` 出来"**。
`scenes/game.tscn` / `hud.tscn` / `main_menu.tscn` / `settlement.tscn` / `main.tscn` 是**真实场景**，
在编辑器里能直接预览、拖拽布局、把报错定位到具体节点；对应的 `.gd` 只做 `@onready` 绑定 + 填数据 + 接信号。
（用户明确要求过：根节点、相机、UI 如果编辑器里什么都看不到，美术没法预览、布局没法拖、报错难定位。）
`game.gd` 因此用 `@onready var sim: Simulation = $Simulation` 这类绑定，**不能**用 `Game.new()` 直接实例化；
测试里必须 `preload("res://scenes/game.tscn").instantiate()`。

> **坑（踩过一次，全程静默）**：`theme` 属性只有 `Control` / `Window` 有。挂在 `CanvasLayer` 上
> **不会报任何错**，但整棵 UI 会回落 Godot 默认深色主题——浅色卡片变灰、深色字压在深色底上不可读。
> 所以主题挂在 `PanelContainer` 这类 `Control` 上（主菜单/结算的根本来就是 `Control`，
> 直接用共享资源 `resources/theme_light.tres`）。`tests/wiring_probe.tscn` 专门查这一类静默失败。

> **缩放语义（已修订）**：放大**不再把乘客/线路本身画大**，而是把站与站、人与人之间拉开。
> 世界坐标仍交给 `Camera2D` 缩放（间距自然被拉开），但渲染层里所有"看起来该恒定大小"的东西
> ——站点环、乘客点、线宽、进度环、车辆段方框、热力光晕——都要经 `Config.view_px(v, zoom)` 抵消掉相机放大；
> 人群的散布半径则走 `Config.view_spread(v, zoom)`（按 √zoom 缓慢拉开：放大能看清一个个乘客，
> 人又还围着本站）。手感由 `Config.VIEW_SIZE_POW` / `VIEW_SPREAD_POW` 两个指数决定。
> 线路同时改为**虚线**（`_draw_dashed_polyline()`，白晕/墨色/线路色三层共用同一个 dash）。

> **另一类静默 bug（索引语义）**：`Train.from_idx` / `to_idx` 是**本线 `station_ids` 的下标**，
> 不是全局站点 id。画车必须写成 `sim.stations[line.station_ids[idx]]`——
> 漏掉这层间接寻址会把每条线的列车都画到"全局第 N 号站"上，而低编号站全属于第一条线，
> 表现就是用户报的「**所有列车莫名挤在一条线路上**」。`tests/wiring_probe.tscn` §4 现在用
> **测试侧独立复算**的断言盯住它，并会自证"按旧写法会有几列车画错"（当时是 6/6）。

`game.gd` 负责组装各层并注入引用；`main.gd` 是场景状态机（菜单 → 游戏 → 结算）。

## 2. 核心循环

```
main.gd:_start_game
   → Game.setup(network, mode)
       → Simulation.setup（加载线网、建站、发车、初始化时间/天气/积分）
         mode == "infinite" 时：infinite_mode = true、duration = 0（不看钟）、建 InfiniteDirector
       → 从 game.tscn 里取 GameView / CameraController / WeatherParticles / PassengerLayer / TrainLayer / HUD
每帧 Game._process(delta)
   → Simulation.tick(delta)
       → TimeSystem.tick / WeatherSystem.tick
       → 事件系统 tick（随机事件、升级计时）
       → InfiniteDirector.tick（无限模式：每 wave_seconds 一波，加站加线）
       → 需求生成（泊松式，受时段/天气/事件倍率）
       → 列车运行（移动 / 到站 / 登降 / 车辆段就地加挂 / 延误传播）
       → 乘客耐心衰减、满意度采样
       → 恐慌累积、踩踏判定
       → 失败判定（踩踏 / 瘫痪 / 满意度归零 / 时间到——无限模式跳过"时间到"）
   → 渲染层每帧 queue_redraw 读取模拟状态绘制
   → UI 通过 EventBus.metrics_changed 刷新
```

## 3. 关键机制

### 3.1 乘客 Agent 与寻路
每个乘客持有 `path`（站点序列）与 `path_index`。上车条件：列车停靠本站、且列车下一站 == 乘客路径下一站；下车即 `path_index++`，到终点记为 `ARRIVED`（计入吞吐量），中间站即换乘（回到站台等下一线列车）。

寻路**不是单纯的最短路**，而是带代价的加权搜索（`Simulation.path_find(origin, dest, p_info, p_conformity)`）：

| 代价项 | 常量 | 默认值 | 含义 |
| ------ | ---- | ------ | ---- |
| 拥挤代价 | `CONGESTION_WEIGHT` | 2.2 | 目标站密度超过 `CROWD_THRESHOLD`(0.6) 后按超出量加成 → **乘客会绕开爆站** |
| 换乘成本 | `TRANSFER_COST` | 2.0 | 每换乘一次加固定代价 |
| 封站惩罚 | `CLOSED_PENALTY` | 8.0 | 封站站点几乎不可通行 |
| 跳站惩罚 | `SKIP_PENALTY` | 1.5 | 被跳站列车经过的站点代价上升 |
| 溢出惩罚 | `OVERFLOW_PENALTY` | 4.0 | 站台排队超过容量时加成 |

乘客还会**定期重算路径**：`REROUTE_INTERVAL`(18s) 冷却，每 tick 最多 `REROUTE_BUDGET`(6) 人；
只有耐心低于 0.6 的乘客才会考虑改道（`info_level` 与 `conformity` 参与决策与代价权重）。

### 3.2 延误传播
列车 `delay` 由事件（信号故障）注入并自然衰减；晚点列车在换乘站停靠时，把部分延误传染给其他线路的列车，形成级联。

### 3.3 恐慌与踩踏
站点密度超过 0.85 后，`panic` 按「超出量 × (0.6 + 从众性)」累积；达到 1.0 触发踩踏，扣安全分 0.5 并清零部分恐慌。安全分归零 → 失败。

### 3.4 成分云与三段式视野
**旧描述「缩放 `zoom < 0.6` 时合并为成分云」已失效。** 现在由**相机档位**驱动：

- `CameraController` 按当前地图几何动态算出三档锚点 `overview_zoom` / `mid_zoom` / `fore_zoom`
  （全貌装下整张图、中景约 4 条平均边长、近景约 1.4 条），三档至少相差 1.3 倍，两端允许弹性越界、手停约 0.3s 回弹到最近档；
  通过 `GameView.set_zoom_bands()` 注入渲染层。
- `GameView._cloud_blend()`：`zoom <= overview` → 云权重 1.0；`zoom >= mid` → 0.0；中间线性交叉淡化。
- 云权重同时让**热力图淡出**（`_draw_heatmap(1.0 - cloud * 0.75)`），避免云和热力打架。
- **一朵云 = 该站四种状态各一团软斑**：按黄金角错开、面积随各状态人数占比变化、外圈白色描边，
  恐慌状态额外加紫环。不再是「加权成一个单色实心圆」。
- 相机稳定在某档时（`is_settled()`）站点圆环由空心变实心（`○ → ●`）。

### 3.5 时间驱动
需求曲线 `Config.DEMAND_CURVE`（早高峰 2.0、晚高峰 2.2），耐心衰减与从众性按时段变化；背景色按 `PERIOD_BG` 每帧 `lerp` 平滑过渡。天气倍率与昼夜叠加。

### 3.6 车辆段与编组延长
「加车」（凭空生成新车）已下线，运力增长改走**车辆段**。核心改动是**编组不再整列下线**——
车始终在线上跑，只是"就地多停几秒挂一节"：

- `Line` 持有 `depot_built` / `depot_station_idx` / `depot_station_override` / `depot_upgrades` / `pending_couples`。
  段站由 `_choose_depot_station_idx()` 决定：优先取线网 JSON 的 `depot_station`（`NetworkLoader` 读进
  `depot_station_override`），否则选**离线路中点最近的非换乘站**（换乘站 +100 分惩罚）。
- `Train` 持有 `cars`、`capacity = cars * Config.DEPOT["car_capacity"]`、`coupling` / `couple_timer` / `couple_total`；
  状态机只有 `MOVING` / `DWELL`（**`IN_DEPOT` 已删除**）。
- 玩家操作 `upgrade_train` 两段式：未建段 → 扣 `depot_build_cost()` 建段；已建段 → 扣 `depot_upgrade_cost()`
  并 `pending_couples += 1`（只是**下达指令**，不指定具体车）。
- **兑现**在 `_arrive_train()` 末尾：`_try_start_coupling(t, ln, sid, st)` 判定「本站是段站 + 有未兑现指令 +
  该车未在挂 + `cars < max_cars`」，命中则置 `coupling/couple_total/couple_timer`
  并把 `t.dwell_timer = maxf(t.dwell_timer, t.couple_total)`——**沿用原有的停站计时器**，不新增状态分支。
- `_update_trains()` 的 DWELL 分支先递减 `dwell_timer`、若在挂再递减 `couple_timer`，
  两者都 ≤0 才 `_finish_coupling()`（`cars += cars_per_upgrade` → `refresh_capacity()` →
  `depot_upgrades += 1` → `pending_couples -= 1`）然后 `_depart_train()`。**车队规模与相位都不变。**
- 费用与工时**随客流负荷浮动**（`_demand_load()` 把「时刻需求 × 天气」映射到 0..1，
  `depot_phase()` 给出 平峰/常态/高峰）：价格 `lerpf(0.75, 1.35, load)`、占站台 `lerpf(5.0, 12.0, load)`。
  同线再加 `1 + 次数 × cost_growth` 递增。
- 设计意图即用户要求的「**分时规划**」：同一件事平峰更便宜、占站台更短，而买来的定员要到高峰才用得上。

**如何验证**（五个无头工具 + 一个可视化工具，跑法见 `tests/`）：
- `tests/depot_bench.tscn` —— 车辆段手感基准（策略 `none` / `build` / `greedy` / `offpeak` / `late`），
  输出总分/服务人数/满意度/峰值密度/指令时段分布。`none` 策略必须与改造前**逐位相同**，否则说明改造有副作用。
- `tests/op_price_test.tscn` —— A/B/C/D 定点断言（操作扣费、段站选址、分时定价、就地加挂），25 项。
- `tests/ui_smoke_test.tscn` —— **HUD / GameView 运行时冒烟** 32 项。这一点很重要：GDScript 对
  `sim.xxx()` 是**动态调用**，删掉一个模拟层函数后，UI 里残留的调用**编译期查不出来**，
  只有真的把 `HUD._process()` 跑起来才会炸（本项目确实这样抓到过一次"加挂中"文案串台）。
  它会 `preload("res://scenes/hud.tscn").instantiate()`（**不能** `HUD.new()`，节点绑定全是 `@onready`）、
  pump `HUD._process`、遍历选择态与车辆段四态、断言按钮价格与置灰、用 `Line.coupling_train()` 确认"车确实在挂"、
  最后 await 帧让 `GameView._draw()` 真跑一遍。为可测性，`GameView` 暴露了纯函数 `cloud_blend_for(zoom)`。
- `tests/infinite_test.tscn` —— 无限模式验收 24 项：新站不越界、扩张后仍全站可达、能顶满线路上限、
  跑过 400s 不触发"时间到"、普通模式不被带坏。
- `tests/wiring_probe.tscn` —— **运行时接线自检**，专抓静默失败：`theme` 是否真的解析成浅色卡片、
  渲染层的 `sim` 有没有接、材质有没有挂上（没挂 → 着色器是死代码）、`TrainLayer` 有没有建出 `LineTrainView`。
- `tests/shot.tscn` —— 可视化核对，**必须开真窗口**（`--headless` 是空渲染器，视口纹理里什么都没有）。
  它会存一帧，0.8 秒后再存一帧并打印**像素差**——模拟已冻住，所以差异只可能来自着色器/自绘动画，
  这是"动效到底有没有在动"的客观判据。**必须多档灵敏度**：背景点阵漂移很慢，单帧只差 1~2/255，
  用单一阈值（如 >8）会得出"没有动效"的错误结论。
- 五个无头工具失败时都以退出码 1 结束，可直接接 CI。
- **踩过的坑（都会静默失败）**：
  - `theme` 只能挂 `Control` / `Window`；挂在 `CanvasLayer` 上不报错，但整棵 UI 回落默认深色主题。
  - GDScript 的运行时错误会**中断 `_ready()` 的剩余部分**，连带跳过末尾的 `get_tree().quit()`
    → headless 进程永久挂死且零输出。判据是「无输出又不退出 = 有错误」，不是"跑得慢"。
    因此所有测试都在 `_ready()` 开头挂了超时兜底，并在命令行加 `--quit-after`。
  - 用 `$out = (& $godot … 2>&1)` 捕获输出时，进程挂住会**完全看不到输出**（stdout 缓冲到进程结束）。
    诊断挂死要直接跑、不捕获。
  - `--check-only --script res://x.gd` **不注册 autoload**，凡引用 `EventBus` 的脚本必报
    `Identifier not found: EventBus`——那不是真错误。

## 4. 性能考量

- 乘客为 `RefCounted` 数据对象，到站即从活跃列表移除，控制内存。
- 渲染用 `_draw` + `GradientTexture2D` 径向热力光晕，避免逐像素 shader。
- 成分云在远景下把「逐乘客绘制」降为「逐站点绘制」，显著减少 draw call。
- 乘客点目前是**逐点 `draw_texture_rect`**（`PassengerLayer._draw`），挂了点着色器之后仍然每帧全量重绘；
  屏幕上的点数量级是几百，暂时够用。**若后续要上几千个点，应换 `MultiMeshInstance2D`**（`passenger_dot.gdshader`
  的 `COLOR` / `VERTEX` 约定本来就是照这个设计的），这也是 `组员任务清单.md` 里 A4 那条的落点。
- 模拟与渲染解耦：渲染可整体关闭（如后台），模拟仍独立运行。
