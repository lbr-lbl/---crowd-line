# 架构说明

《涌线 -- crowd line》采用**三层解耦 + 事件总线**架构：模拟层独立演算涌现，渲染层与 UI 层只读模拟状态、通过信号通信。

---

## 1. 整体分层

```
┌─────────────────────────────────────────────┐
│  模拟层 simulation/                          │
│  Simulation（编排）                           │
│    ├ TimeSystem    昼夜循环、时段参数          │
│    ├ WeatherSystem 天气与参数倍率              │
│    ├ Station/Line/Train/Passenger 数据类      │
│    ├ ScoreSystem  积分五维                    │
│    └ EventSystem  随机事件 + 肉鸽升级          │
└──────────────────┬──────────────────────────┘
                   │ 只读查询 / 指令
┌──────────────────▼──────────────────────────┐
│  渲染层 rendering/                           │
│  GameView._draw（背景/热力/线路/站点/列车/乘客）│
│  CameraController（三段式视野、点击选择）       │
│  WeatherParticles（雨/雪 GPU 粒子）            │
└──────────────────┬──────────────────────────┘
                   │ EventBus 信号
┌──────────────────▼──────────────────────────┐
│  UI 层 ui/                                   │
│  HUD / MainMenu / Settlement / UpgradeUI     │
└─────────────────────────────────────────────┘
```

`game.gd` 负责组装各层并注入引用；`main.gd` 是场景状态机（菜单 → 游戏 → 结算）。

---

## 2. 核心循环

```
main.gd:_start_game
   → Game.setup(network, mode)
       → Simulation.setup（加载线网、建站、发车、初始化时间/天气/积分）
       → 创建 GameView / CameraController / WeatherParticles / HUD
每帧 Game._process(delta)
   → Simulation.tick(delta)
       → TimeSystem.tick / WeatherSystem.tick
       → 事件系统 tick（随机事件、升级计时）
       → 需求生成（泊松式，受时段/天气/事件倍率）
       → 列车运行（移动 / 到站 / 登降 / 延误传播）
       → 乘客耐心衰减、满意度采样
       → 恐慌累积、踩踏判定
       → 失败判定（踩踏 / 瘫痪 / 满意度归零 / 时间到）
   → 渲染层每帧 queue_redraw 读取模拟状态绘制
   → UI 通过 EventBus.metrics_changed 刷新
```

## 3. 关键机制

### 3.1 乘客 Agent 与寻路
每个乘客持有 `path`（BFS 最短站点序列）与 `path_index`。上车条件：列车停靠本站、且列车下一站 == 乘客路径下一站；下车即 `path_index++`，到终点记为 `ARRIVED`（计入吞吐量），中间站即换乘（回到站台等下一线列车）。

### 3.2 延误传播
列车 `delay` 由事件（信号故障）注入并自然衰减；晚点列车在换乘站停靠时，把部分延误传染给其他线路的列车，形成级联。

### 3.3 恐慌与踩踏
站点密度超过 0.85 后，`panic` 按「超出量 × (0.6 + 从众性)」累积；达到 1.0 触发踩踏，扣安全分 0.5 并清零部分恐慌。安全分归零 → 失败。

### 3.4 成分云与三段式视野
缩放 `zoom < 0.6` 时，乘客按状态分桶合成色块（绿/黄/红/紫加权，透明度随密度），否则绘制独立圆点；`0.6..0.95` 区间两者交叉淡入淡出。

### 3.5 时间驱动
需求曲线 `Config.DEMAND_CURVE`（早高峰 2.0、晚高峰 2.2），耐心衰减与从众性按时段变化；背景色按 `PERIOD_BG` 每帧 `lerp` 平滑过渡。天气倍率与昼夜叠加。

---

## 4. 性能考量

- 乘客为 `RefCounted` 数据对象，到站即从活跃列表移除，控制内存。
- 渲染用 `_draw` + `GradientTexture2D` 径向热力光晕，避免逐像素 shader。
- 成分云在远景下把「逐乘客绘制」降为「逐站点绘制」，显著减少 draw call。
- 模拟与渲染解耦：渲染可整体关闭（如后台），模拟仍独立运行。
