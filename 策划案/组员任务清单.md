## 0. 先读这一页（5 分钟）

### 0.1 我们在做什么

涌现式地铁调度沙盒。玩家管一张真实城市地铁线网，**不能直接控制乘客**，只能限流、升级车辆（车辆段编组）、封站、跳站、广播，改规则改参数。乘客只有几条简单规则（去目的地、选最短路、避开拥挤、跟人走、耐心有限、会慌），人一多，早高峰潮汐、换乘通道堵死、一条线晚点拖垮全网、突然爆大客流——全是系统自己涌出来的，不是脚本。

**所有工作都要服务一句话：让玩家从画面上看懂"涌"正在发生。**

### 0.2 分工原则

| 人 | 角色 | 负责层 | 主战场 |
| --- | --- | --- | --- |
| lbr | 主程 / 策划 | 模拟层 simulation/ | 涌现机制、调参、无限模式 |
| **组员 A**（有 Unity 项目经验） | 视觉反馈负责人 | 渲染层 rendering/ + shaders/ | 粒子、后处理、主题氛围、性能 |
| **组员 B**（基础较弱） | 交互与内容负责人 | UI 层 ui/ + 数据 + 打包 | 按钮、面板、音效、线网数据、文档 |

### 0.3 五条铁律（违反会直接搞崩别人的活）

1. **不要改不属于你的文件。** 文件所有权见 §5.1。要改共享文件，先在群里说一声。
2. **GDScript 缩进必须和该文件现状一致。** 本项目两种风格混用：`scripts/rendering/camera_controller.gd`、`scripts/simulation/simulation.gd`、`scripts/simulation/network_loader.gd` 用 **4 个空格**；其余大多数文件（`config.gd`、`hud.gd`、`game.gd` 等）用 **Tab**。改哪个文件就跟随哪个文件，**绝对不要跨文件复制粘贴代码块**。编辑器里打开「显示空白字符」。
3. **线网 JSON 里 `station.id` 必须等于它在 `stations` 数组中的下标，且从 0 连续。** 之前台北线网在这里跳号（id 是 0,1,2,5,6…），直接导致 `stations[sid]` 越界崩溃。
4. **渲染层和 UI 层禁止直接修改模拟层内部状态。** 只能读公开字段、调查询方法、发 EventBus 信号。
5. **一个提交做一件事**，提交信息中文动词开头（`新增 / 修复 / 重构 / 优化 / 文档`）。不提交 `.godot/`。

## 2. 组员 A（有 Unity 项目经验）—— 视觉反馈层

**你的使命：让所有数字都看得见。** 模拟层算出一堆密度、恐慌、延误、天气倍率，玩家看不懂数字，只能看懂画面。把参数 → 画面这件事包下来。

### A1. 天气视觉补全（短期·最高优先级）

**目标**：让"晴/阴/小雨/暴雨/雪/雾"六种天气在画面上有六种明显不同的长相。

**改哪**：`scripts/rendering/weather_particles.gd`（已有雨雪），新建 `scripts/rendering/weather_ground.gd`（地面）与 `scripts/rendering/weather_clouds.gd`（云）

**做什么**：
1. **雾**：新建一个全屏 `ColorRect`（或 CanvasLayer），`alpha` 随 `sim.weather.intensity` 平滑上升，颜色偏灰蓝。要求是"能见度下降"，**不是黑屏**。
2. **云飘过**：雨/雪来临前，画几团缓慢横向移动的半透明云。需要"预告"信号——先跟 lbr 约：在 `weather_system.gd` 加 `target_weather` + 提前若干秒广播，你只读它。
3. **地面积水/积雪**：全屏底部渐变或站点下方的色带，**随时间累积**（雨下久了才湿，雪下久了才白），雨停后缓慢消退。

**接口**（只读，别写回）：
```gdscript
sim.weather.get_weather()          # "clear" / "light_rain" / "snow" / "fog" ...
sim.weather.intensity              # 0..1 平滑过渡值
sim.weather.is_raining()           # bool
sim.weather.is_snowing()           # bool
sim.weather.get_label()            # "小雨"
```

**验收**：手动把天气依次设成 `fog` / `heavy_rain` / `snow` 各看一遍；雾要能感到"看不清远景"；积水明显滞后于雨；帧率不低于 55。

---

### A2. 后处理与压力反馈（短期）

**目标**：全网压力越大，画面越"紧"。这是策划案 §12.3 要的 Bloom / 色差 / 暗角。

**改哪**：新建 `shaders/post_process.gdshader` + `scripts/rendering/post_process.gd`（CanvasLayer 挂在最上层，一个全屏 `ColorRect` 挂 `ShaderMaterial`）

**做什么**：
- **Bloom**：晚高峰、暴雨、恐慌上升时增强
- **色差**：全网平均密度高时轻微 RGB 分离
- **暗角**：一直有，压力高时加重
- 所有参数 `lerp` 平滑过渡，**绝不能突变**

**接口**：读 `sim.score.safety`、各站点 `sim.get_station(sid).density`、`sim.weather`、`sim.time.get_period()`。

**验收**：平峰画面干净到几乎看不出后处理；恐慌/暴雨时肉眼可见"画面炸开"；给一组优化前后帧率数字。

### A3. 三段视野衔接动画：云 ↔ 点（中期）

**目标**：策划案 §11.3 那句"缩小：小圆点逐渐融合成云；放大：云逐渐分裂，小圆点从云中**析出**"。

**现状**：`game_view.gd` 里 `_cloud_blend()` 已经做了云和点的**交叉淡入淡出**（`zoom` 从 `overview` 到 `mid` 之间线性过渡），但只是"淡"，不是"析出"。

**改哪**：`scripts/rendering/game_view.gd` —— **这个文件归 lbr**，所以：你先在自己分支上做实验，做成之后跟 lbr 一起合。或者提方案，让 lbr 在 `_draw_dots` 里加位置插值。

**想法**：让每个乘客点在 `cloud` 值高的阶段，位置被"吸引"到它所属站点的云中心，`cloud` 降到 0 的过程中位置 lerp 回真实位置，看起来就是"从云里掉出来"。

**验收**：从全貌滚到中景，点不是"淡入"，而是**从云里析出并散开**。

### A4. 性能预算（中期）

**目标**：硬核池（50+ 站、上千乘客）稳 60fps。

**现状**：`game_view.gd` 的 `_draw_dots()` 是**逐个乘客 `draw_circle`**，乘客一多直接跪。

**做什么**：
1. 先做一个**调试面板**（按 F1 开关）：FPS、本帧绘制耗时、活跃乘客数、draw call 数。**没有测量就没有优化。**
2. 候选手段：乘客改 `MultiMeshInstance2D` 实例化绘制 / 分帧绘制热力图 / 成分云复用低分辨率密度纹理。
3. 给出优化前后的三组数字（入门池 / 进阶池 / 硬核池）。

**Unity 经验迁移**：Godot 的 `MultiMeshInstance2D` ≈ Unity 的 `Graphics.DrawMeshInstanced`；`_draw()` ≈ `OnGUI` + 立即模式 GL；调试数值用 Godot 编辑器的 **Remote Inspector** 实时改，别改代码调。

### A5. 把渲染层的魔法数字收出来（短期·顺手）

**现状**：`game_view.gd` 里散着一堆插值常量（`0.75` / `0.42` / `0.55` / `3.0` / `4.2` …）。

**做什么**：收到 `config.gd` 或渲染层自己的常量区，命名清楚（`CLOUD_BLEND_STRENGTH`、`DOT_SPREAD_NEAR` …）。

**验收**：改一个常量就能调整云/点的视觉密度，不用翻函数体。

## 3. 组员 B（基础较弱）—— 交互、内容与工程

**你的使命：让每个操作都有回应。** 玩家点一下按钮，画面必须有反应、有解释、有记录、有声音。任务都设计成**低风险、可见效果、有明确验收标准**，按顺序做。

> **学习捷径**：`scripts/ui/hud.gd`（356 行）就是这个项目 UI 的**标准模板**——`_build_ui()` 里 `new()` + `add_child()` 程序化建界面，`_process()` 里刷新，`EventBus` 信号驱动更新。照着它抄结构就行。注意它现在还演示了两件事：**按钮文案随状态变化**（`upgrade_train` 的 `tooltip_text` 会按"未建段/待加挂/加挂中/已满"改写），以及**价格拼进按钮 + 资源不足自动置灰**（`_refresh_op_buttons()`），你可以照这两个思路做动态提示。

### B1. 操作栏完善（短期·第一个做）

**目标**：底部五个操作按钮（限流 / 升级车辆 / 封站 / 跳站 / 广播）从"灰格子"变成"看得懂的操作台"。

**改哪**：`scripts/ui/hud.gd`（`_build_ui()` 里 `for op in ["limit", "upgrade_train", "close", "skip", "broadcast"]` 那一段）

> **注意**：第三个按钮已从旧的"加车"（凭空生成新车）改为"升级车辆"（车辆段加挂），
> 而且它是**两段式**的——第一次点是建车辆段，之后每次点是**下达一张加挂指令**（不是立刻加长，
> 而是等下一列停靠段站的列车就地多停几秒挂一节）。做提示时要能反映这个状态机，
> 并且**按钮文案里要带价格**——五个操作现在都要花资源了。

**做什么**：
1. **加图标**：每个按钮配图标（emoji 或单色线稿，统一风格）。
2. **悬停/长按详情**：最简做法是 `Button.tooltip_text = "限流：降低进站速率，代价是满意度下降"`；想更好就自己写个面板，鼠标悬停 0.3 秒 / 触摸长按 0.5 秒弹出。
3. **底部提示句**：加上效果图里那句话——"各操作由图标显示，悬停或长按为详细信息"。
4. **按钮禁用态要看得懂**：现在没选中目标时是全禁用，加一行灰字提示"点击站点或线路以选择目标"。

**已有基础**：`_op_name(op)` 返回中文名，`_op_cost(op)` 返回当前价格（车辆段会随客流负荷浮动），
`_refresh_op_buttons()` 已演示"把价格拼进按钮文案 + 资源不够自动置灰"，`_on_op(op)` 已连好
`sim.apply_operation(op, target)`。**照 `_refresh_op_buttons()` 的思路改就行。**

**验收**：五个按钮都有图标；悬停出说明；长按也能出；点下去功能和改之前完全一致。

### B2. 暂停弹出 + 快进/慢放（短期）

**目标**：效果图顶部那个框——⏸ 暂停、◁◁ 慢放、▶▶ 快进，并显示当前积分。

**改哪**：新建 `scripts/ui/pause_panel.gd`，在 `game.gd` 里挂上（`game.gd` 归 lbr，加东西前说一声）

**已有基础**：
- `EventBus` 里已经有 `signal pause_requested(paused: bool)`——**埋好了但没人接**
- `game.gd` 有 `paused_flag`，`_process()` 里已经在判它

**实现提示**：
- **推荐**：在 `Game._process()` 里给 `sim.tick(delta * speed)` 传倍率（`speed = 0.5 / 1.0 / 2.0 / 4.0`）。
- **不推荐**：`Engine.time_scale`——它会连 UI 动画和 Tween 一起变速，容易出玄学问题。
- 快捷键：空格暂停、`[` `]` 调速。

**验收**：暂停时模拟停住但 UI 还能点；快进时客流肉眼可见变快；暂停时不触发结算。

**做什么**：按时间**倒序**列出：事件触发、踩踏、封站、限流、列车延误、升级选择。每条带游戏内时间 + 图标 + 一句话。

**直接就能接的信号**（都在 `event_bus.gd`，白送）：

```
event_triggered(event)      upgrade_offer(choices)     stampede(station_id)

```

### B5. 线网数据管线（短期·零风险，适合练手）

**目标**：把「加一张线网」变成一件有检查、不会崩的事。

**做什么**：
1. **写一个校验脚本**（Godot 的 `EditorScript`、或一个 headless GDScript、甚至先写独立 Python 都行）。检查每张线网 JSON：
   - `station.id` 是否从 0 **严格连续**（这是头号崩溃源）
   - `lines[].station_ids` 引用的 id 是否都真实存在
   - 有没有**孤立站点**（不属于任何线路）
   - 每条线的 `station_ids` 长度是否 ≥ 2
   - 坐标是否落在 `0..1600 × 0..1000`
2. **用校验过的格式新增 2~3 张线网**。策划案 §5 里还没做的城市：哥本哈根 M1/M2、曼谷 BTS 素坤逸线、杭州 1 号线、武汉 2+4 号线、新加坡 MRT 早期线网。

**格式**（`resources/networks/*.json`）：
```json
{
  "id": "copenhagen_m1",
  "name": "哥本哈根 M1",
  "city": "哥本哈根",
  "difficulty": 1,
  "stations": [
    {"id": 0, "name": "Vanløse", "x": 160, "y": 480, "capacity": 120}
  ],
  "lines": [
    {"id": 0, "name": "M1", "color": "#00e5ff", "headway": 12.0,
     "speed": 120.0, "station_ids": [0, 1, 2, 3, 4, 5, 6]}
  ]
}
```
> **换乘站不用显式声明**——同一个 `station.id` 出现在多条线的 `station_ids` 里就自动是换乘站。

**验收**：校验脚本对现有 7 张线网全部通过；新增线网进游戏不报错、线路连得对、换乘站能换乘。

### 5.2 接口约定（照 `项目规范.md` §5 走）

**EventBus 已埋好的信号**（`scripts/autoload/event_bus.gd`，直接用）：
```
hour_changed(hour)              period_changed(period)         weather_changed(weather)
passenger_arrived(station_id)   station_density_changed(id, density, queue)
station_panic(id, level)        train_delayed(line_id, delay)  stampede(station_id)
event_triggered(event)          upgrade_offer(choices)         upgrade_chosen(upgrade)
metrics_changed(metrics)        game_over(reason, metrics)
selection_changed(target)       operation_applied(op, target_id)
toast(message)                  pause_requested(paused)        ← 目前没人接，B2 去接
```

**模拟层只读入口**：
```gdscript
sim.get_station(sid) -> Station      sim.get_line(lid) -> Line
sim.train_world_position(t) -> Vector2
sim.time.get_hour() / get_period() / get_hour_label()
sim.weather.get_weather() / get_label() / intensity / is_raining() / is_snowing()
sim.score.total_score() / metrics() / live_metrics()
sim.resources  sim.elapsed  sim.duration  sim.running
```

**模拟层指令入口**（只有这些能改变模拟状态）：
```gdscript
sim.apply_operation(op, target_id)    # "limit" / "upgrade_train" / "close" / "skip" / "broadcast"
                                      # upgrade_train 是两段式：未建段则建段，已建段则下达一张加挂指令
sim.apply_upgrade(id)                 sim.apply_event(id)

# 操作价格（做按钮文案/置灰用）
Config.operation_cost(op)             # limit 15 / close 12 / skip 12 / broadcast 20

# 车辆段查询（做 UI 提示用，都是只读）
sim.depot_build_cost(lid)   sim.depot_upgrade_cost(lid)
sim.depot_busy(lid)         sim.depot_phase()   sim.depot_couple_dwell()
# Line 上的字段：depot_built / depot_upgrades / pending_couples / depot_station_id() / depot_busy() / max_cars()
# Train 上的字段：cars / capacity / coupling / couple_progress()
```

**加新 UI 面板的标准做法**（程序化构建，不建 `.tscn`）：
```gdscript
var layer := CanvasLayer.new()
layer.layer = 25                       # HUD=10, 升级=20, 教程=30
add_child(layer)
var panel := MyPanel.new()
layer.add_child(panel)
panel.setup(sim)
```
