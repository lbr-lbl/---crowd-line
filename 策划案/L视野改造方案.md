# L 视野改造方案（乘客个体 + 站台闸门）

> 这份是**动手前**的方案，用来先对齐顺序与技术选择。确认后我按阶段实现，每阶段都出图验证。

## 为什么先谈顺序

两条需求是耦合的：

- 乘客要**站在站台上**。站台的位置、朝向、宽度、以及"这一队排在哪"，全部由站台几何决定。
- 如果先做乘客，等站台从"一个白点"展开成"一段带闸门的站台"，乘客的站位、朝向、排队形状**都要重做一遍**。

所以建议**站台先行**，乘客后做。

---

## 阶段一：站台与闸门（对应需求 2）

### 已经解决了一半的地方

`RouteGeometry` 现在已经在做这件事：

> 每个站点算一条"长轴"，并为**每一条经过该站的线路**分配一个泊位偏移（按 line.id 排序）。

也就是说——**"一个站多条线就有多个站台"所需的数据结构已经存在了**，现在只是把它画成一个白胶囊。改成"每个泊位画一条独立站台"是渲染层的活，不需要动几何层。

### 要做的

| 需求 | 做法 |
| --- | --- |
| 站点放大、展开为站台 | L 视野（zoom ≥ fore）时，胶囊的**半宽**按视野插值放大，读成一条站台；全貌/中景仍是最小符号（不破坏已有的"符号随缩放"规则） |
| 站台扩容会变大 | 半长/半宽乘 `effective_capacity()` 的归一化值（现在 `base_half` 已经用了容量，只是幅度很小，要拉开差距） |
| 多条线 = 多个站台 | 直接用现成的泊位偏移，每条线一条站台 |
| 列车进站/出站时闸门开合 | 开口量 `gate(0..1)`：查 `sim.trains` 里有没有"本线、本车、`from_idx == to_idx`、该站"的车 → 有则开到 1，走则回到 0，用 `Tween`/指数趋近做过渡 |
| 简约表示 + 着色器 | 站台与闸门用一个程序化着色器：沿站台长度方向画刻度线当闸门，`gate` 作为 uniform 决定线段的开口 |

### 验证方式

- 截图 + **像素采样**（对比"有车停站"与"无车"两帧的闸门区域亮度差）——这是上一轮闪电学到的：图形效果不能"看着像就算"。
- 复用一个截图开关（类似 `dwell`）把相机锁到某站，强制"有车/无车"两态各出一张。

## 阶段二：乘客个体图形（对应需求 1）

### 图形

圆头 + **正三角（男）/ 倒三角（女）**身体，全部用 SDF 程序化绘制，**不需要新素材**。
性别只是三角朝向翻转，不额外增加分支。

### 动作（用状态驱动，不写死动画）

| 动作 | 触发条件 | 表现 |
| --- | --- | --- |
| 站立 + 呼吸 | 默认 | 身体的纵向缩放做极慢的正弦（约 0.3Hz），几乎察觉不到，但一片人一起呼吸就能看出"活的" |
| 踱步 | 等待时间较长、站台不挤 | 沿站台方向做小幅往返位移 + 朝向翻转 |
| 跑步 | 正在上车 / 换乘赶时间 | 位移速度最快、身体前倾（三角倾斜）、步频高 |
| 拥挤推开 | 站台密度超过阈值 | 以自己为中心做**小幅径向推挤**，密度越高抖动越强、越不规则 |

"涌现感"的关键是**拥挤推开**：单个人看不出什么，一片人被挤成波浪才好看。所以它的参数要与 `station.queue.size() / capacity` 挂钩，而不是随机。

### 每乘客需要传给着色器的数据

现有 `passenger_dot.gdshader` 已经用顶点位置做相位（我上一轮改的），要扩成：

`state`（0 站 / 1 走 / 2 跑 / 3 挤）＋ `sex` ＋ `phase` ＋ `urgency`。

→ 打包进顶点色 + 一个附加属性即可，不必每个乘客一个材质。

### 新加入的人由外向内浮现

生成点取"站点圆外一圈"，向站台位置插值 + 透明度渐入。**这一条要落在渲染层**（不要把模拟层的生成位置改到站外，那会影响寻路和容量判定）。

### ⚠ 一个需要你拍板的耦合点

**"先下后上"**这件事：

- 如果只是**渲染层假装**（画面上先下后上，但载客计数同时进行），视觉会和数字打架——玩家会看到"人还在下，车已经显示满了"。
- 我的建议是**在模拟层真的按先下后上出队**：先卸客再上客。这样画面与数字一致，但会**略微改变停站时长与运力**（等于改平衡），需要重跑 14 组基线。

这属于"观感改动偷偷变成数值改动"，是我一直在守的那条线，所以必须你同意再动。

## 阶段三：上下车时序

在阶段二的基础上，把"下车的人往外走、上车的人往车门走"画出来。
数据源需要一个"这个乘客正在上下车"的标志——**需要在 `Passenger` 上加一个字段**，这是本项与模拟层唯一的耦合。

---

## 风险与我会守的底线

1. **性能**：现在乘客是 8px 的点，改成"头 + 三角"后每个乘客的片元开销上升，而 L 视野恰好是同屏乘客最多的时候。
   我会给 L 视野设一个绘制上限（例如最多画前 N 个），并在改动前后各测一次帧率/耗时。
2. **不破坏已建立的缩放规则**：站点与列车现在都跟 `Config.view_grow` 一起缩放，站台展开必须挂在同一套规则上，不能再引入第二套。
3. **每一阶段独立可验证**：阶段一单独出图就算完成，不会"做一半挂在那里"。
4. **我做不到的部分我会明说**：手感（呼吸多快、抖动多强、闸门开合多急）我给的值都是"技术上说得过去"，最终要你点过才算数。

## 阶段一 · 追加修正（用户反馈）

> 「L 视野线路直接张开为直线，然后闸机沿着这条直线」

原来站台跟着**该线在本站的局部走向**旋转，遇到拐弯的站（例如太子）两条站台就会歪成交叉状，很乱。

现在改成：

- 站台**一律水平**，不再跟随局部走向；
- **每条线一个站台，按线序上下叠放**（多个站台时读起来像"多层站台"）；
- **轨道从站台正中笔直穿过**，并往两端延伸一点 —— 即"线路在这里是直的"；
- **闸机沿这条直线排布**，开门时从中间让开缺口；
- 站点符号在左侧，用一条细线连到站台组。

### 一个仍然存在的视觉交叠，需要你确认是否属于本意

**地图上那条真实的线**（折线）仍然按真实走向穿过站点，所以近景下会看到
"真实的斜线"和"拉直后的水平站台轨道"交叉。

我只拉直了**站台/闸机这一段**。如果你要的是**整条线在 L 视野下都拉直成直线**
（线路图式，站点沿线等距排布），那是另一档改动：它会改变整个 L 视野的空间感，
并且列车位置、乘客站位都要跟着换成"沿直线参数化"。

请确认是前者（当前实现）还是后者。

## 阶段一 · 修正二：真正的「站台内部」视图（用户澄清）

> 「我的意思是站点展开为全屏那样嘛，就像进到了站台里，然后线路把它捋直像站台里那样子」

前面那版理解错了：我只把**站台那一段**摆成水平线，地图本身还是地图。用户要的是**换一个视图**。

现在实现为**独立的一层**：`scripts/rendering/station_interior.gd`（`StationInterior extends CanvasLayer`）

- 挂在 `CanvasLayer`（layer 6）上 -> **屏幕固定**，不随相机平移缩放，所以读起来是"进到站里了"；
- 背景一层磨砂白，把地图压到后面；
- **每条经过该站的线画成一条水平直线轨道**，按 `line.id` 从上到下堆叠（"线路被捋直"）；
- 站台 + 闸机沿直线排布，闸机开合仍由"本线是否有车停站"驱动；
- **列车**按"距本站几个站 + 段内进度"映射到直线上的位置，从左右进出，停站时带一圈环；
- 只在**近景 L** 淡入（`FADE_LO/HI` 由相机缩放插值），中景/全貌完全隐藏 -> **对地图视图零影响**；
- 展开哪一站：优先**选中的站点**，没选中就取离相机中心最近的一站。

### 已知待调（等用户看过再动）

1. **顶部站名与 HUD 的时钟重叠** —— 站名写在 y=46，正好撞上 HUD 顶部的时刻/暂停键。要么把站名下移，要么进入该视图时淡出 HUD 的顶部条。
2. **地图仍略微透出**（磨砂层 0.94 不透明度），斜向的线路还能看到一点。
3. 闸机刻度 9 道仍偏密。

### 下一阶段

乘客个体图形（圆头 + 正/倒三角、四种动作）**落在这一层里**，站在站台上 ——
不再是画在地图上的点。这也印证了"先站台后乘客"的顺序是对的。

## 阶段一 · 修正三：平滑进入 / UI 错乱 / 列车抽搐 / 闸机（用户反馈）

> 「不够平滑，没有真的进到里面的感觉，而且UI错乱，显示的列车抽搐。还有闸机先每侧只用两个吧，然后是平行于线路的。」

### 1. 列车抽搐（真 bug，两个原因叠加）

第一版用「**站数 + 段内进度**」把列车映射到直线上，于是：

- **各段站距不等**，按站数映射时，同样的真实速度在不同段上换算成不同的屏幕速度 → 忽快忽慢；
- **终点站掉头**时 `to_idx` 往回走，`(from-si)` / `(to-si)` 会从 `+k` 直接跳到 `-k` → 列车瞬间穿屏。

改成按**沿线路的累计弧长**取比例：弧长单调，掉头只是"比例开始变小"，车会平滑地反向走回去。
再叠一层每列车的位置指数平滑，吸收残余跳变。

### 2. UI 错乱

- 站名从 y=46 下移到 `h*0.17`，让开 HUD 顶栏的时钟与暂停/加速键；
- 新增 `HUD.set_interior_mode()`：进入站台视图时，把**地图专属**的三件（视野滑钮 / 视野提示 / 时间轴）淡出——
  它们是"看线网"的工具，站台视图里留着就是两套 UI 叠在一起。评级、时钟、资源、日志、操作按钮保留。

### 3. 不够平滑 / 没有"进去"的感觉

- 淡入速率 `9.0 -> 4.2`，过渡带 `0.45~0.85 -> 0.30~0.95`（给足缓冲，不再"啪"地跳出来）；
- 加**缩放推进**：以**该站在屏幕上的坐标**为锚点，把整个画板从 1.55x 收到 1.0x，配合淡入读起来像"走进站台"。

> ⚠ 这里的坑：**不能用 `draw_set_transform(pos, ...)` 做这个缩放**。那个 API 会把**绘制原点一起搬走**，
> 结果整块内容被推到右下角（实测截图就是只有右下角一块白色）。
> 正确做法是改 **Control 自身的 `pivot_offset` + `scale`** —— 缩放绕锚点，绘制坐标一个都不用动。

### 4. 闸机

从 9 道竖线改为**每侧两个**（左 `0.30 / 0.40`、右 `0.60 / 0.70`），并且**平行于线路**（短横线），
不再是垂直于线路的"栅栏"。开门时靠中间的先让开。

### 仍待处理

- HUD 的 **toast（如"暴雨来袭"）** 仍会和站名重叠 —— 它是屏幕居中偏上的，需要一起挪或者进站台视图时上移。
- 地图在磨砂层下仍略微可见（0.955 不透明度），斜向线路还能看到一点。

## 阶段一 · 修正四：列车"无车也开来开去" + 操作栏行为（用户反馈）

> 「明明站内没车还是会显示车开来开去；进入站内玩家操作栏常现，拖动或按住屏幕则下降消失，松开上浮。」

### 1. 站内没车却显示列车（真 bug）

第一版把**整条线**的弧长比例映射到站台这一条屏幕上，于是**远在别的站的车也会出现在这块站台里**。

改成：以**本站的弧长**为中心开一个"看得见的窗口"（约前后一站半 `1.7 × 平均站距`），
窗口内的车才画，窗口外直接不画 —— 这样"站内没车"就是真的没车。

### 2. 操作栏在站台视图里的行为

- 站台视图里**常现**（那里没有"先选中目标"这一步，所以不该要求点选才出现）；
- **拖动或按住屏幕时下降躲开，松开再浮上来** —— 由 `Game._process` 把
  `camera_ctrl.dragging` 同步给 `HUD.set_hold_mode()`；
- 进入站台视图时若没有选中站点，自动选中当前展开的那一站，操作栏才有意义。

### 3. 「站台应该是实际画面，而不是 UI 覆盖层」（**尚未做，下一轮**）

用户澄清：站台不是叠在画面上的一层 UI，**站台本身就是画面**，而且站台内部可以做得更大、**可以拖动查看**。

这等于把这一层从 `CanvasLayer` **搬进世界空间**：作为相机看到的东西，拖动就是相机平移（现成能力），
缩放也自然作用于它。对应的改动：

- 把绘制从 `StationInterior(CanvasLayer)` 挪到**世界层**（`game_view` 或它的子 Node2D），
  尺寸按世界单位给大（一站距约 260 世界单位），于是"放大 + 拖动"就能看站台里面；
- 磨砂底不再是全屏矩形，而是**世界空间里的一块大站台**；相应地，进入近景时把地图其它内容淡出，
  否则会和真实线网抢画面；
- 列车映射逻辑（弧长 + 局部窗口）**可以原样搬过去**，那部分不用重写。

**这一轮没有半途改**：搬家的中途状态会留下一个坏掉的视图，而渲染层的半成品正是我这几轮反复出问题的地方。

## 阶段一 · 修正五：层序 + 操作面板冲突（用户反馈）

> 「只有滑动时候会跳一下，应该是冲突了」
> 「站台看着不像"进去了"；站点的画面也很奇怪，可以上网搜一下学别人怎么做，但要简约一点」

### 1. 操作面板"滑动时跳一下" = 两个驱动源打架（已修）

`set_hold_mode()` 让面板降下去，而 `_refresh_op_buttons()` **每帧**又因为 `any_visible` 为真把它升回来 —— 互相抢。
改成**动画只由一处决定**：`set_hold_mode()` 只记录状态，`_refresh_op_buttons()` 里按
`(not _hold) if _interior_on else any_visible` 统一决策。

### 2. 白底之上还叠着地图层（已修）

白底只盖住了**先画**的内容；地图列车、雨雪粒子、氛围层都是 `game_view` 的**兄弟节点**，
绘制顺序在它之后，所以照样叠在站台上 —— 这就是"看着不像进到站里"的结构性原因。
现在：进站台视图时 **地图列车隐**（站台内已重画列车）、**雨雪隐**、**乘客点保留**（人该站在站台上）。

### 3. 站台画面"很奇怪" —— 下一步的改法（有依据）

参考了地铁站台的常见画法与等距示意（[平台剖面/轨道床](https://escholarship.mcgill.ca/downloads/wh246t31p?locale=en)、
[等距站台示意](https://www.istockphoto.com/FR/illustrations/subway-station-isometric)、
[像素风地铁内饰](https://assetstore.unity.com/packages/3d/props/interior/metro-3d-pixel-art-subway-for-boomer-fps-vr-129896)），
**站台之所以读不出来，是因为缺少那几个一眼认出的特征**。按"简约"取舍，只加三个：

1. **站台面用中灰**（现在 0.905 接近白，和底分不开）——真实站台是水泥灰；
2. **开门那一侧加一条"盲道/警戒带"** —— 这是"这是站台"最认得出的符号，一条暖色窄带即可；
3. **轨道槽**比站台暗一档，两条轨枕画成细亮线；
4. （可选）**柱子** —— 沿站台每 240 世界单位一根短竖条，是"室内"最便宜的暗示。

全部矢量，不加素材。

# 阶段一定稿：单线站台视图（用户选定）

## 两条硬约束（下一轮不要再重新推一遍）

1. **一屏的世界预算**
   近景锚点缩放约 **9**，即 **1 世界单位 ≈ 9 屏幕像素**；屏幕 1280×720
   -> 可见范围约 **142 × 80 世界单位**。
   **"两线 × (2 轨 + 2 台)"= 4 台 4 槽，几何上装不进 80 世界单位。**
   所以站台视图**一次只显示一条线**，由左上角线色圆点切换。
2. **所有站台尺寸按"屏幕像素 ÷ 9"来定，不要凭感觉给数。**
   当前一组（总高 ≈ 71 < 80，留上下余量）：
   `PLAT_W 20`（≈180px，**乘客就站在这个带里，别再压薄**）、`TRENCH_H 7`、`TRACK_GAP 5`、
   `TRACK_DY 6`、`PLAT_EDGE_GAP 2`、`GAUGE 1.8`、`TACTILE_H 2.4`、
   `GATE_X ±48/±26/±8`（6 道，屏幕约 ±430px）、`TRAIN_LEN 60`（≈540px）、`TRAIN_REACH 320`。

## 已验证的画面（用"展开后的第二帧"确认）

上下两条黄色盲道带（开门侧）、站台白带、深色轨道槽 + 亮钢轨、

## 验证方法（重要，之前一直是错的）

# 核查结论：先下后上**模拟层已经是对的**（不需要改、不需要重跑基线）

原计划把"先下后上"当成一处模拟层改动。实际读代码发现**顺序本来就是对的**：

`simulation.gd` 的 `_arrive_train()`：

- **777~796 行：下车**（遍历车上乘客 -> 到站的下车 -> 到终点记服务、换乘的回站台排队）；
- **798~814 行：上车**（从站台队列里按"本车发车方向的下一站"筛人 -> 装车）。

下车整段跑完才开始上车，所以**载客数字与画面的"先下后上"是一致的**，
原先担心的"人还在下、车已显示满"不会发生。

## 因此这一轮省掉的工作

- 不需要改模拟层；
- **不需要重跑 14 组基线**（原本以为要，那是这轮最大的一块成本）。

## 唯一还缺的是**画面**（属于已推迟的"乘客统一处理"）

两件事都发生在同一个瞬间，所以视觉上缺过程：

1. 上车的乘客**瞬间从站台消失**（`state` 变 RIDING 后就不再被乘客层绘制）——缺"跑向车门"；
2. 下车的乘客**瞬间出现在站台上**——缺"走出车门"。

要做的话最小改法是：模拟层在上下车时往站上追加一个**纯表现用的标记**（位置 + 时间戳，不参与任何判定），
渲染层拿它画 0.3~0.4 秒的"跑动"图形。**这不会改平衡**，所以依然不用重跑基线。

# 修正七：零延迟聚焦 / 乘客破碎感 / 站台站位

- **聚焦零延迟**：M 段预选吸附不再插值，`target_pos` 与 `camera.position` **一起**直接设成站心
  （只设 target 的话，`PAN_SMOOTH=9` 还会拖约 110ms）。实测偏离 0.00。
- **乘客"破碎感"的真根因**：身体用的是 `if (t >= 0 && t <= 1) halfw = ...`，范围外 `halfw = -1`，
  于是 SDF 在身体边界**跳变**，`fwidth()` 一爆，抗锯齿就把边撕成锯齿。
  改成**无分支锥形**：`body = max(abs(uv.x) - halfw, max(BODY_TOP - y, y - BODY_BOT))`（`t` 先 `clamp`），
  全程连续，边就稳了。
- **动效幅度**：呼吸 7%→**16%**、摆动 3%→**7.5%**、新增上下轻晃 3%。
  原来那点幅度在 36 像素的方块上等于没动（用户反馈"没有动效"）。
- **站位**：L 视野只画**当前线、当前站**的人，按"下一站索引比本站大/小"分派到**下/上站台**，
  站位与站台几何**同源**（都用 `GameView` 的 `TRACK_DY / TRENCH_H / PLAT_EDGE_GAP / PLAT_W`）。
- 方块尺寸 30→**36 屏幕像素**。

# 修正八 · 最近数轮定稿（补记，之前漏同步）

## 站位与线路

- **站台视图一次只显示一条线**；左上角**线色圆点**切换（当前线全亮、其余半透明）。
- **乘客严格按线路过滤**（用户选定）：只画"下一站在本线上"的人。
  代价：多线站可见乘客很少（实测太子 38 人只筛出 1 人）；单线站是全的（九龙湾 7/7）。
- 站位**散开**，不站成一排：序号哈希出稳定伪随机位置（沿站台 ±62 世界单位）。

## 缩放锚点（关键：站台几何是绝对世界单位，缩放也必须绝对）

- `fore_zoom` **固定 9.0**（1 世界单位 ≈ 9 像素）。原来按平均站距算 → 每个线网近景大小不同。
- `mid_zoom = sqrt(overview_zoom * fore_zoom)` —— 取**对数中点**，
  于是 H→M 与 M→L 的滚轮距离在**任何线网**下相等（原来跟站距走，只有无限模式碰巧接近）。

## 站台几何（世界单位）

`PLAT_W 26`、`TRENCH_H 7`、`TRACK_GAP 5`、`TRACK_DY 6`、`PLAT_EDGE_GAP 2`、
`GAUGE 1.8`、`TACTILE_H 2.4`、`PLAT_LEN 6000`（故意极长，端点永不进画面）、
`TRAIN_LEN 120`（车身高度 = 槽高 7，不能比槽高，否则盖住闸机）、`TRAIN_REACH 320`。

## 闸机 = 黑线上的开口

- **轨道与站台之间一条黑线**，它就是"站台沿 = 一道墙"的可视化；
- **闸机就是这条线上的断口**：关着 = 线连续（只留 0.4 世界单位的小缝标记位置），
  开着 = 断开，`gap_half = 0.4 + 2.8 * (1 - vis)`（全开半宽 2.8，洞宽 5.6）；
- **4 道**闸机、跨度 **±42**（`GATE_MAX = 42` 必须与之一致）；
- 开度阈值 `thr = 0.55 - near * 0.35`（中间先开、外侧后开，**全开时全开**）；
- **只有停站列车那一侧**的闸机开（`gate_open_side`，方向 `>0` 走下行、`<0` 走上行）。

### 教训：开口大小决定"挤不挤"

8 道 ±70、开口半宽 5.0 → **墙上全是大洞，人直着走过去，完全不挤**。
4 道 ±42、开口半宽 2.8（洞宽 5.6）对**碰撞直径 3.8** 的人 → 一次只过一个多，才会挤。

## 乘客图形与动效

- **程序化 SDF**：圆头 + 正三角（男）/ 倒三角（女）；头与身体**必须相交**
  （留缝会分裂成两块，像"枫叶"）；
- **平滑并集 `smin(head, body, 0.075)`**：硬 `min()` 会在接合处留两个凹角，
  加三角底两角共四个尖 —— 这就是"枫叶感"的**真正来源**（一直都有，与缝无关）；
- **相位必须在顶点着色器算**（`varying float v_ph`）：片元里的 `VERTEX` 是逐像素插值的，
  `floor`+哈希会在方块内部跳变 → 形状碎成"离散像素点"；
- 动效只做**刚体变换**：上下平动 bob（2.2%）+ 以**脚跟**为支点整体摆动 lean（约 3 度）。
  幅度不能大（8 度时头横向位移最大，看起来像"以脖子为支点"）；**绝不形变**
  （缩放身体纵向范围会像细菌蠕动/身体爆开）。
- 乘客方块 48 屏幕像素；碰撞距离 `view_px(34)`；**间距与大小必须同量纲（都用 view_px）**。

## 上下车（现为**渲染层近似**，有已知缺陷）

用**队列差分**推断：上一帧在等、这一帧**真的离开 WAITING 状态**才算上车
（只是被线路过滤掉的不算，否则寻路重算会让一群人凭空出现/消失）。
上下车都**必须走闸机口**（路径两段：横向到闸机 → 纵向穿开口）。
**已知缺陷**：上下车动画期间的人不参与碰撞 → 同一道闸口会**互穿**。

互穿从 0.28 收到 2.50（目标 2.83），**没有完全消除**，且观感更差，**已按用户要求回退**。

## 相机与 HUD

## 测试方法（这几轮最贵的收获）

- **全量错误扫描**，不预设错误内容：
