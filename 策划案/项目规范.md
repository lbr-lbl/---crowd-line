# 项目规范

本文档定义《涌线 -- crowd line》项目的目录、命名、数据格式、模块接口与扩展约定，作为多人协作与后续迭代的统一标准。

---

## 1. 目录规范

```
scripts/
├── autoload/       # 全局单例（事件总线、持久状态、线路池）
├── simulation/     # 模拟层：纯逻辑，不依赖渲染（含 infinite_director.gd）
├── rendering/      # 渲染层：只读模拟层数据，用 _draw 绘制
│                   #   game_view / passenger_layer / train_layer / line_train_view
│                   #   background_layer / camera_controller / weather_particles
├── ui/             # UI 层脚本：只做 @onready 绑定 + 填数据 + 接信号（界面本体在 scenes/）
├── config.gd       # 全局常量、调色板、曲线、难度预设、车辆段参数、无限模式参数
├── game.gd         # 单局编排器（@onready 绑定 game.tscn 的节点）
└── main.gd         # 入口状态机
resources/networks/ # 线网 JSON 数据
resources/real_world.json # **内容侧集中表**：每张图的场馆 / 气候带 / 禁用天气、各类活动的客流规模
resources/theme_light.tres # 主菜单/结算共用的亮色主题（含下拉箭头）
scenes/             # 真实场景：main / main_menu / game / hud / settlement
shaders/            # canvas_item 着色器：bg_paper / passenger_dot / train_body
assets/             # 外部素材：icons/（22 个游戏内图标）、UI/、头图 SVG、panel_bg.png
tests/              # 五个无头验收工具 + 截图工具
tools/              # 一次性工具（从图标总览切图的 python 脚本等）
docs/               # 开发者日志
策划案/              # 策划案、架构说明、本规范、线路池设计、组员任务清单
```

**原则（已修订）**：**界面与单局编排用真实 `.tscn`**，不用 `new()` 拼。理由：全部代码构建时编辑器里看不到任何东西，
美术没法预览、布局没法拖、报错也难定位到节点。`.gd` 只负责 `@onready` 绑定 + 刷新 + 接信号。
**注意**：`game.gd` / `hud.gd` / `settlement.gd` 等因为用 `@onready` 绑节点，**不能** `X.new()` 直接实例化，
必须 `preload("res://scenes/x.tscn").instantiate()`（测试里踩过这个坑）。

**主题（theme）只能挂在 `Control` / `Window` 上**：挂在 `CanvasLayer` 上不会报错，但整棵 UI 会静默回落
Godot 默认深色主题（本项目出现过一次：浅色卡片变灰、深色字压在深色底上不可读）。所以统一挂在
`PanelContainer` 这类 `Control` 上。`tests/wiring_probe.tscn` 专门查这类静默失败。

## 2. 命名规范

| 对象               | 规则                       | 示例                             |
| ------------------ | -------------------------- | -------------------------------- |
| 文件名             | snake_case                 | `time_system.gd`                 |
| 类名（class_name） | PascalCase                 | `TimeSystem`、`Simulation`       |
| 函数 / 变量        | snake_case                 | `path_find`、`entry_multiplier`  |
| 常量               | UPPER_SNAKE                | `COLOR_PANIC`、`CONGESTION_WEIGHT` |
| 私有成员           | 下划线前缀                 | `_build_adjacency`、`_spawn_one` |
| 信号               | 动词短语 snake_case        | `game_over`、`selection_changed` |
| 枚举               | 类内 `enum`，PascalCase 值 | `Train.TrainState.MOVING`        |

**类型标注**：尽量使用静态类型（`var x: int`、`Array[Station]`）。注意 `Array[X]` 与普通 `Array` 不能直接互相赋值，返回 `Array[X]` 的函数必须显式构建类型化数组（见 `NetworkLoader.build_stations`、`Simulation.path_find`）。

## 3. 分层与依赖方向

```
模拟层 (simulation)  ← 只依赖 Config、EventBus
   ↑ 只读
渲染层 (rendering)   ← 读模拟层数据，只依赖 Config
UI 层 (ui)          ← 读模拟层、发指令；通过 EventBus 通信
game.gd             ← 组装三层，注入引用
main.gd             ← 场景状态机（菜单/游戏/结算）
```

- 各层之间**通过 EventBus 信号解耦**，禁止渲染层/UI 层直接修改模拟层内部状态。
- 模拟层对外只暴露：公开字段（只读）与查询方法（`get_station`、`get_line`、`train_world_position` 等）和指令方法（`apply_operation`、`apply_upgrade`、`apply_event`）。

## 4. 数据格式

### 4.1 线网 JSON（`resources/networks/*.json`）

```json
{
  "id": "wenzhou_s1",
  "name": "温州 S1 线",
  "city": "温州",
  "difficulty": 1,
  "stations": [
    {"id": 0, "name": "桐岭", "x": 160, "y": 480, "capacity": 120}
  ],
  "lines": [
    {"id": 0, "name": "S1", "color": "#00e5ff", "headway": 12.0,
     "speed": 120.0, "station_ids": [0, 1, 2, 3, 4, 5, 6]}
  ]
}
```

- `station.id` 从 0 连续；`lines[].station_ids` 引用站点 id，顺序即线路走向。
- **换乘站**由「同一站点出现在多条线路」自动推导，无需显式声明。
- 坐标单位为世界像素，建议保持在 `0..1600 × 0..1000` 区间，保持相对位置即可（无需地理精确）。

### 4.2 升级 / 事件（`event_system.gd` 中的静态定义）

```gdscript
{"id": "quick_gate", "name": "快速闸机", "desc": "进站速度 +20%，但满意度 -5%", "icon": "⚡"}
{"id": "concert", "name": "演唱会散场", "desc": "某站短时大客流涌入", "icon": "🎤"}
```

- 升级 / 事件只改参数，不改规则。效果统一在 `Simulation.apply_upgrade` / `Simulation.apply_event` 中用 `match id` 实现。

### 4.3 车辆段参数（`Config.DEPOT`）

「加车」已下线，运力增长统一走车辆段。参数集中在 `Config.DEPOT`：

| 键 | 默认值 | 含义 |
| -- | ------ | ---- |
| `build_cost` | 55.0 | 建车辆段的一次性费用（会乘分时系数） |
| `base_cost` | 40.0 | 首次加挂费用（同样乘分时系数） |
| `cost_growth` | 0.55 | 该线每多加挂一次，费用 ×(1 + 次数 × 该值) |
| `couple_dwell_flat` | 5.0 | 平峰时加挂占用的站台秒数 |
| `couple_dwell_peak` | 12.0 | 高峰时加挂占用的站台秒数 |
| `cost_flat` | 0.75 | 平峰价格系数 |
| `cost_peak` | 1.35 | 高峰价格系数 |
| `load_low` / `load_high` | 0.5 / 2.0 | 客流负荷（时刻需求 × 天气）映射到 0..1 的区间 |
| `car_capacity` | 40 | 每节车厢定员 |
| `min_cars` / `max_cars` | 2 / 6 | 初始编组 / 编组上限 |
| `cars_per_upgrade` | 1 | 每次延长几节 |

**加挂是"就地"的**：下单后不是把车抽走，而是线路上**下一列停靠段站的列车**在该站多停
`couple_dwell` 秒（期间照常开门上下客），然后 +1 节。**车队规模全程不变**，段站是关键状态位
（`Line.pending_couples` 表示有未兑现的指令，`Train.coupling` 表示某车正在挂）。

运行时另有两个倍率（肉鸽升级可改）：`Simulation.depot_cost_scale`（加挂费用倍率）、
`Simulation.depot_duration_scale`（加挂占站台时长倍率）。

### 4.4 操作定价（`Config.OPERATION_COST`）

「加车」之外的四个操作不再是免费按钮——资源有多个出口，才有取舍：

| 操作 | 键 | 默认价 |
| ---- | -- | ------ |
| 限流 | `limit` | 15.0 |
| 封站 | `close` | 12.0 |
| 跳站 | `skip` | 12.0 |
| 广播 | `broadcast` | 20.0 |

统一入口是 `Config.operation_cost(op) -> float`；模拟层用 `Simulation._spend(amount, what)` 扣费，
余额不足会 `EventBus.toast` 提示并**不改变任何状态**。HUD 每帧调 `_op_cost(op)` 把价格拼到按钮文案上，
资源不够时按钮自动置灰（`_refresh_op_buttons()`）。

### 4.5 现实依据集中表（`resources/real_world.json`）

**地图 JSON 只描述拓扑，不掺内容。** "温州演唱会只在奥体中心""香港不下雪"这类现实约束全部写在这里：

```jsonc
{
  "weather":  { "typhoon": {"climates": ["typhoon"], "weight": 3},        // 需要什么气候带 + 出现权重
                "clear":   {"climates": ["*"], "weight": 30, "opening": true} },  // opening=true 才能当开局天气
  "networks": { "wenzhou_s1": { "climates": ["rainy","typhoon","humid"],
                                "forbidden_weather": ["snow"],
                                "venues": [ {"name":"温州奥体中心","station":"奥体中心","kinds":["concert","sports"]} ] } },
  "event_kinds": { "concert": {"venue_kind":"concert","label":"演唱会散场","burst":18} }
}
```

- 读取口是 `RealWorld`（`scripts/simulation/real_world.gd`）：`allowed_weather()` / `roll_weather(net, opening)` /
  `pick_venue(net, kind)` / `available_event_kinds(net)`。
- 事件分两类：**场馆类**（只落在 `venues` 里声明的站）与**设施/天气类**（哪站都可能，按天气可行性筛）。
- **开局天气只从标了 `"opening": true` 的温和天气里抽**：实测不加这个限制，开局抽到"酷热"（需求 ×1.22）
  撞上早高峰，重庆 hardcore 的失败时间会从 ~350s 掉到 76.6s。
- **表写错不会报错，只会静默失效**（例如场馆里站名打成"奥体城"而地图里是"奥体中心"，
  结果就是这张图永远不发生演唱会事件）。所以 `tests/real_world_test.tscn` 把"表里的站名必须存在于对应地图"
  当成硬断言，**改了表一定要跑它**。

### 4.6 运营日志（`OpsLog`）

记录**特殊事件 / 特殊天气 / 玩家操作**，每条带开始与结束时间（同时存游戏内时钟标签与 `elapsed`）：

| 方法 | 用途 |
| ---- | ---- |
| `note(kind, text, elapsed, clock)` | 有**持续时段**的记录（天气）：会自动把上一条同类"进行中"的收尾 |
| `note_point(kind, text, elapsed, clock)` | **瞬时**记录（事件、玩家操作）：开始 = 结束 |

- 类别用 `kind` 区分：`event` / `weather` / `operation` / `wave`；HUD 按类别上色。
- 写入后发 `EventBus.log_updated`，日志面板据此重建（面板关着时不重建，省开销）。
- **玩家操作的写入点在 `Simulation._spend()`**——所有花钱的操作都从这一个出口过，所以不会漏记。

### 4.7 视野滑钮（`ViewSlider`）

右侧竖直轨道：**3 个站点 = 三段视野锚点**，站点上下各多出一小段轨道表示"还能再缩放一点"
（相机确实允许越界回弹），**列车表示当前视野**。
值域 0..1 与缩放之间用**对数映射**——三段锚点本身是几何级数（各自 ×1.3），只有对数映射才能让三个站点等距。
拖动通过 `CameraController.set_zoom_target()` 走与滚轮**同一套回弹规则**；反过来每帧用相机真实缩放同步滑块位置。

## 5. 模块接口约定

### 5.1 EventBus 信号（`autoload/event_bus.gd`）

| 信号                                                                            | 含义                       |
| ------------------------------------------------------------------------------- | -------------------------- |
| `hour_changed(hour)` / `period_changed(period)`                                 | 时间推进 / 时段切换        |
| `weather_changed(weather)`                                                      | 天气切换                   |
| `passenger_arrived(station_id)`                                                 | 乘客到站                   |
| `station_density_changed(id, density, queue)`                                   | 站点密度变化（渲染热力图） |
| `station_panic(id, level)`                                                      | 站点恐慌上升               |
| `stampede(station_id)`                                                          | 踩踏事件                   |
| `event_triggered(event)` / `upgrade_offer(choices)` / `upgrade_chosen(upgrade)` | 事件 / 肉鸽                |
| `metrics_changed(metrics)`                                                      | 实时积分                   |
| `game_over(reason, metrics)`                                                    | 结束                       |
| `selection_changed(target)` / `operation_applied(op, id)`                       | 交互                       |
| `toast(message)`                                                                | 顶部提示                   |
| `pause_requested(paused)`                                                       | 暂停 / 继续（**尚无监听方**） |

### 5.2 时间系统接口（`TimeSystem.gd`）

`get_hour()`、`get_period()`、`get_demand_multiplier()`、`get_patience_decay()`、`get_conformity()`。

### 5.3 天气系统接口（`WeatherSystem.gd`）

`get_weather()`、`get_label()`、`get_demand_multiplier()`、`get_speed_multiplier()`、`is_raining()`、`is_snowing()`；另有 `intensity`（0..1 强度）与 `trigger_timed(weather, duration)`（临时天气）。

## 6. 视觉规范

| 元素       | 规范                                                                        |
| ---------- | --------------------------------------------------------------------------- |
| 背景       | **亮色"纸面"**：渐变底 + 极淡点阵（`TIME` 缓慢漂移 + 相机视差）+ 斜向光泽 + 收边暗角，`shaders/bg_paper.gdshader`；底色随时段走（`Config.PERIOD_BG`） |
| 线路       | 高饱和霓虹（`Config.LINE_PALETTE`），夜间降低饱和度（`GameView._vibrancy`） |
| 站点       | 深藏青圆环 + 白心，大小表示容量，换乘站加亮                                  |
| 乘客状态色 | 绿=正常 `#4ade80`、黄=等待 `#ffd23f`、红=拥堵 `#ff5c5c`、紫=恐慌 `#c084fc`。**`Config.ink(c, amount)` 的 amount 是"往墨色 `#182236` 里兑多少"**：云用 0.18~0.30，乘客点只用 0.08（否则黄→橄榄、绿发灰） |
| 热力图     | 绿→黄→红→白，`Config.heat_color(density)`                                   |
| 成分云     | **由相机档位驱动**（`GameView.set_zoom_bands` + `cloud_blend_for(zoom)`），在「全貌档 → 中景档」之间交叉淡化；每个非空状态各一团软斑，黄金角错开 |
| UI         | **白色半透明卡片 `rgba(1,1,1,0.93)` + 细描边 + 柔和投影，深藏青字**；界面本体在 `scenes/hud.tscn` 等真实场景里 |
| 图标       | `assets/icons/` 23 个（22 个从图标总览切出 + 本地生成的 `icon_chevron_down.png`）。**原图是"白底透明"**（图标总览本身也是白底透明，需先合成到深底才看得见），用在浅色按钮上必须靠 `Button/colors/icon_*_color` 染色，否则白图标会消失 |
| 虚线       | 线路画成虚线：`game_view._draw_dashed_polyline()` 按段拆开调 `draw_dashed_line`，三层（白晕 / 墨色 / 线路色）用**同一个 dash**，相位对齐后才是"带白边的虚线" |
| 主题资源   | 亮色主题抽成共享资源 `resources/theme_light.tres`（`main_menu.tscn` / `settlement.tscn` 的根 `Control` 引用它）。**`theme` 只能挂 `Control`/`Window`**——挂在 `CanvasLayer` 上不报错但整棵 UI 回落默认深色主题（HUD 踩过这个坑，所以它把主题挂在四个 `PanelContainer` 上） |
| 缩放语义   | **放大 = 把间距拉开，不是把东西画大。** 符号尺寸走 `Config.view_px(v, zoom)`（屏幕上恒定），人群散布半径走 `Config.view_spread(v, zoom)`（按 √zoom 缓慢拉开，既看得见空隙、人又不会撒得满屏都是）。两个指数分别是 `VIEW_SIZE_POW=1.0` / `VIEW_SPREAD_POW=0.5`，调它们就能改手感 |
| 轨道几何   | **共端点的多条线在站点处必须错开**，否则两条线会完全叠在一起。统一由 `RouteGeometry`（`scripts/rendering/route_geometry.gd`）算：每站一个"长轴"（= 各线平均方向的垂线），每条线在本站取一个泊位序号。**折线（`GameView`）、列车位置（`LineTrainView`）、乘客点簇半径（`PassengerLayer`）三处必须共用同一份实例**（由 `GameView.route_geo` 持有、`Game` 注入其余两层），各算一遍一定错位 |
| 站点形状   | 站点是**长条胶囊体**：长轴 = 上述错开方向，长度按经过的线数加长（单线站退化为圆）。用 `_capsule_fill()` / `_capsule_outline()` 画，不用 `draw_style_box`（后者圆角半径是整数，高缩放下会变形） |
| HUD 卡片   | 四张卡片（评级 / 指标 / 时间 / 操作）**平时半透明 0.60，鼠标悬浮或点击（钉住）变不透明**；指标区在左侧、**资源排第一**，左上角只放评级徽章 |

## 7. 扩展指南

### 新增一个线网

1. 在 `resources/networks/` 添加 JSON。
2. **必须**让 `station.id` 等于它在 `stations` 数组中的下标，且从 0 连续——`NetworkLoader.build_stations` 按数组顺序建站，
   而 `build_lines` 把 `station_ids` 的值当下标用，跳号会直接导致 `stations[sid]` 越界崩溃（台北线网曾因此报错）。
3. 在 `scripts/autoload/network_pool.gd` 的 `POOLS` 里把 id 加进对应池的 `members`，否则主菜单抽不到它。

> 注意：主菜单**不再直接列出所有线网**，而是先选「线路池」，再从池里随机抽一张（`NetworkPool.random_network`）。

### 新增一个事件 / 升级

1. 在 `EventSystem.event_pool()` / `upgrade_pool()` 加一条定义。
2. 在 `Simulation.apply_event(id)` / `apply_upgrade(id)` 加 `match` 分支实现效果。

### 新增一个玩家操作

1. `EventBus` 无需改动。
2. 在 `Simulation.apply_operation(op, id)` 加分支。
3. 在 `scenes/hud.tscn` 的 `OpPanel/OpBox/OpRow` 下加一个 `Button`（可参考现成的 `LimitButton`，注意 `icon` 与
   `custom_minimum_size`），再在 `HUD._build_bindings()` 的 `paths` 字典里登记它；文案写 `HUD._op_name()` / `_op_tip()`。
4. 若这个操作要花资源：在 `Config.OPERATION_COST` 加一条，模拟层用 `_spend(Config.operation_cost(op), "…")` 扣费
   （余额不足只 toast、不改任何状态），HUD 侧无需额外改动——`_op_cost()` 与 `_refresh_op_buttons()` 会自动拼价格并按余额置灰。

### 新增 / 修改一个线路池

改 `scripts/autoload/network_pool.gd` 的 `POOLS` 字典（键为池 id）与 `POOL_ORDER` 数组，主菜单下拉会自动出现。
池字段：`label`（显示名）、`desc`（说明）、`mode`（传给 `Simulation.setup` 的难度键，对应 `Config.DIFFICULTY`）、`members`（线网 id 列表）。
新增难度档则在 `Config.DIFFICULTY` 加一条（时长、时间流速、起始时刻、目标吞吐量、积分目标）。

### 改完模拟层 / UI / 渲染层后必须跑的无头工具

```powershell
$g = "D:\下载\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64_console.exe"
$root = "F:\Godot_project\涌线--crowd-line"
# 1) 定点断言（操作扣费 / 段站选址 / 分时定价 / 就地加挂）——25 项
& $g --headless --quit-after 600 --path $root res://tests/op_price_test.tscn

```

视觉改动还要用截图工具**开真窗口**看一眼（`--headless` 是空渲染器，视口纹理里什么都没有）：

```powershell
# <线网> <难度> <缩放> <先跑多少游戏秒> <输出> [取景站号]；不传站号用站点质心取景
& $g --path $root res://tests/shot.tscn -- hongkong_tw_kt advance 2.6 45 res://tests/ref.png
& $g --path $root res://tests/shot.tscn -- scene res://scenes/main.tscn res://tests/_menu.png
```

- **判据：headless 无输出又不退出 = 有错误，不是"跑得慢"。** GDScript 的运行时错误会中断 `_ready()` 的剩余部分，
  连末尾的 `get_tree().quit()` 一起跳过，进程就永远挂着。所以所有测试都在 `_ready()` 开头挂了超时兜底，
  命令行也一律带 `--quit-after`。
- **动效必须用"两帧像素差"证伪，而且要多档灵敏度**：模拟冻住后抓两帧比较，
  背景点阵漂移很慢（单帧只差 1~2/255），只用单一阈值（如 >8）会得出"没有动效"的错误结论。
- **取景别用外接矩形中心**：香港那种 U 形线网的矩形中心是空的，高缩放时会拍出"整屏空白"的假象。
- 用 `$out = (& $g … 2>&1)` 捕获输出时，**进程挂住会完全看不到输出**（stdout 缓冲到进程结束）。
  诊断挂死要直接跑、不捕获。
- `--check-only --script res://x.gd` **不注册 autoload**，凡引用 `EventBus` 的脚本必报
  `Identifier not found: EventBus`——那不是真错误。
- 读中文源码行数要用 `[System.IO.File]::ReadAllLines($f).Count` 或 `Get-Content -Encoding UTF8`；
  PS 5.1 的默认 `Get-Content` 按 GBK 解码，会把行数读少。
- **新增 PNG/SVG 素材后必须跑一次导入**，否则 `.tscn` 里引用它会报
  `No loader found for resource … (expected type: Texture2D)`：
  `& $g --headless --import --path $root`（编辑器扫描时也会自动生成 `.import`，但命令行创建的素材没有）。
- **画世界坐标的东西时，`Train.from_idx` / `to_idx` 是本线 `station_ids` 的下标，不是站点 id**：
  必须 `sim.stations[line.station_ids[idx]]`。漏掉这层间接寻址会把每条线的列车都画到"全局第 N 号站"上，
  表现为「所有列车莫名挤在一条线路上」（`line_train_view.gd` 踩过，`wiring_probe` §4 现在有独立复算的断言盯着）。
